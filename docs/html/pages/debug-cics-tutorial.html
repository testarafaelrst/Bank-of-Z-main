Tutorial: Debug a CICS Transaction

1. Overview

This tutorial walks through debugging the Bank of Z INQCUST COBOL program — the CICS customer inquiry transaction — using IBM Z Open Debug in Visual Studio Code. The debug session is orchestrated by two server-side daemons: the Debug Profile Service (DPS) and the Remote Debug Service (RDS).

The Debug Profile Service manages debug profiles to identify which transactions to intercept, without affecting other transactions running on the same CICS region. The Remote Debug Service routes a debug session to your specific VS Code instance, acting as the protocol bridge between CICS and the Debug Adapter Protocol (DAP) that VS Code understands.

By the end of this tutorial, you will be able to:

  • Configure a Zowe zOpenDebug profile to target your z/OS environment
  • Create a Debug Profile Service (DPS) profile to intercept the INQCUST transaction
  • Trigger a CICS transaction from the Bank of Z web application
  • Attach VS Code to a parked debug session and step through COBOL source code
  • Inspect variables, set breakpoints, and navigate program flow

2. System Architecture

The following diagram illustrates how IBM Z Open Debug connects VS Code to a running CICS task through the Debug Profile Service and Remote Debug Service.

graph TD A[Bank of Z Web Application] -->|Customer Inquiry Request| B[z/OS Connect] B -->|CICS Request| C[CICS Region] C -->|Intercept matching profile| D[Debug Profile Service\nDPS - Port 8192] D -->|Parks transaction| E[Remote Debug Service\nRDS - Port 8194] E -->|DAP Protocol| F[VS Code\nIBM Z Open Debug Extension] F -->|Breakpoints / Variables / Step Controls| E E -->|Resume / Terminate| D D -->|Resume task| C

The interception flow is user-scoped: only transactions running under the TSO user ID specified in the DPS profile are intercepted. All other users’ transactions continue unaffected on the same CICS region.

The table below summarises the role of each component and the default ports used in the Bank of Z environment:

Component Role Default Port
Debug Profile Service (DPS) Stores and serves debug profiles; intercepts matching CICS tasks 8192
Remote Debug Service (RDS) Protocol bridge between DPS and VS Code DAP 8194
IBM Z Open Debug (VS Code extension) DAP client; renders source, breakpoints, and variables —

3. Prerequisites

Before starting this tutorial, ensure that you have:

  • Completed the Quick Start and successfully built and deployed Bank of Z.
  • VS Code with the IBM Developer for z/OS Enterprise Edition (IDzEE) extension pack installed. This includes IBM Z Open Debug.
  • The Bank of Z CICS region is running and you can reach the OMEN transaction.
  • The INQCUST load module was compiled with the TEST or TEST(SOURCE) compiler option so that a side-file listing exists.

4. How It Works

Z Open Debug uses two server-side daemons and a CICS-side intercept to connect VS Code to a running CICS task. The high-level connection path is:

CODE 
VS Code  ⟷  Remote Debug Server (RDS, port 8194)  ⟷  Debug Profile Service (DPS, port 8192)  ⟷  CICS region

The sequence below shows the order of operations from profile activation through to VS Code attachment:

sequenceDiagram participant Dev as Developer (VS Code) participant DPS as Debug Profile Service (DPS) participant RDS as Remote Debug Service (RDS) participant CICS as CICS Region participant App as Bank of Z Web App Dev->>DPS: Create & Activate DPS Profile (INQCUST / CICSUSER) App->>CICS: Customer Inquiry (e.g. C0001) CICS->>DPS: Check for matching debug profile DPS-->>CICS: Profile match found — intercept task CICS->>RDS: Park task and notify RDS Dev->>RDS: Press F5 — Connect to parked session RDS-->>Dev: Attach DAP session; open INQCUST source Dev->>CICS: Step / Inspect / Continue CICS-->>Dev: Variable values, program counter updates Dev->>CICS: Disconnect — task resumes normally

When the DPS profile is active, any invocation of INQCUST by the matched TSO user ID causes CICS to suspend the task and park it with the RDS, which then waits for VS Code to attach.

5. Step 1 — Configure the Zowe zOpenDebug Profile

The Bank of Z repository ships a pre-configured zOpenDebug profile block in zowe.config.json with DPS port 8192 and RDS port 8194. You only need to supply your host name and credentials in zowe.config.user.json.

5.1 Set the Host in zowe.config.user.json

Copy zowe.config.user.json.template to zowe.config.user.json, then open the file and set the host property for the bank-of-z profile:

JSON 
{
  "profiles": {
    "bank-of-z": {
      "properties": {
        "host": "192.168.1.10"
      },
      "secure": ["user", "password"]
    }
  }
}

Replace 192.168.1.10 with the IP address or hostname of your z/OS system.

5.2 Store Credentials in the Zowe Secure Credential Store

Run the following command and enter your TSO user ID and password when prompted:

BASH 
zowe config secure

5.3 Verify the Profile Resolves Correctly

BASH 
zowe config list --root

Confirm that bank-of-z.zOpenDebug appears under defaults and that the following values are present:

  • dpsPort: 8192
  • rdsPort: 8194

6. Step 2 — Verify the Launch Configuration

The repository includes a ready-to-use debug launch configuration in .vscode/launch.json. Open the file and confirm it matches the following:

JSON 
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "zOpenDebug",
      "request": "launch",
      "name": "Z Open Debug: Connect to a parked debug session",
      "connection": {
        "type": "zowe",
        "name": "bank-of-z.zOpenDebug"
      }
    }
  ]
}

The type: "zOpenDebug" and request: "launch" combination instructs Z Open Debug to connect to a session that is already parked on the DPS — that is, a CICS task that has been intercepted and is waiting for a debugger to attach. The Zowe profile (bank-of-z.zOpenDebug) supplies all connection details, so no further configuration is required.

7. Step 3 — Create a Debug Profile Service Profile

The DPS profile tells CICS which programs to intercept and for which user. You create this profile through the IBM Z Open Debug view in VS Code.

7.1 Open the Zowe Explorer Panel

In the VS Code Activity Bar, open the Zowe Explorer panel.

7.2 Navigate to the CICS Debug Profiles Tree

In the Z/OS DEBUGGER PROFILES section, expand the Debug Profiles tree node. Right-click on CICS and select Create.

7.3 Fill In the Profile Details

Field Value
Profile name INQCUST-debug (any descriptive name)
CICS system Your CICS region name, e.g. CICSBOZ
Load module / program INQCUST
Qualified user ID Your TSO user ID, e.g. CICSUSER

Select Save. The profile is registered with the DPS on z/OS.

7.4 Activate the Profile

Right-click the newly created profile and select Activate for Debug. A bug icon with a green dot appears on the profile when it is active.

With the profile active, any invocation of INQCUST under the specified TSO user ID is intercepted by CICS and parked until VS Code attaches.

8. Step 4 — Trigger the CICS Transaction

Open the Bank of Z web application and look up a customer whose ID starts with C (for example, C0001). The UI sends the request through the following path:

graph LR A[Bank of Z Web UI] -->|HTTP Request| B[z/OS Connect] B -->|CICS IPIC| C[CICS Region] C -->|EXEC CICS LINK| D[INQCUST Program] D -->|Profile match — task parked| E[RDS / DPS]

Note: For transactions originating from the web interface, there is a timeout configured in the cics.xml file for z/OS Connect. For this project it is set to 5 minutes. If you need longer debug sessions, edit the requestTimeout attribute of the zosconnect_cicsIpicConnection tag in cics.xml. This file is generated by .setup/setup/setup-zosconnect-server.sh.

9. Step 5 — Attach the Debug Session in VS Code

9.1 Open the Run and Debug View

In VS Code, open the Run and Debug view using the keyboard shortcut Ctrl+Shift+D (Windows/Linux) or ⇧⌘D (macOS).

9.2 Select the Launch Configuration

From the configuration dropdown at the top of the panel, select Z Open Debug: Connect to a parked debug session — the entry defined in .vscode/launch.json.

9.3 Start the Debug Session

Press F5 or click the green Start Debugging arrow.

Z Open Debug contacts the RDS at port 8194, which retrieves the parked session from the DPS at port 8192. VS Code opens the INQCUST source file and the program counter stops at the first intercepted line.

10. Step 6 — Inspect Variables and Step Through Code

Once attached, use the standard VS Code debug toolbar and side panels to inspect and control the running CICS task.

Action Shortcut Description
Continue F5 Run to the next breakpoint or program end
Step Over F10 Execute the current statement; stay at the same call level
Step Into F11 Step into a called sub-program or paragraph
Step Out ⇧F11 Run to the end of the current program or paragraph
Stop ⇧F5 Terminate the debug session; the CICS task abends (ADBS)

The Variables panel in VS Code will display COBOL working storage and linkage section fields as the program executes. You can hover over identifiers in the source editor to inspect their current values inline.

11. Troubleshooting

Symptom Likely Cause Resolution
VS Code cannot connect to a parked session Transaction ran and completed before F5 was pressed; profile was not active Ensure the DPS profile is activated before triggering the transaction, then trigger again
Source not shown — only assembler disassembly Listing file not found or .zdx.json path is wrong Verify the USS listing path in .zdx.json; confirm the build produced a .dbg side file
CICS transaction abends with ADBS Debug session was terminated rather than disconnected Use Disconnect instead of Stop to let the task complete normally
Other users’ transactions are being intercepted DPS profile userId field was left blank or wildcarded Edit the profile and set userId to your specific TSO user ID
RDS connection refused Port 8194 is blocked or the RDS started task is not running Check network access to the z/OS host on port 8194; verify the RDS started task
Breakpoints shown as unverified (hollow circles) Source file in VS Code does not match the listing file on z/OS Ensure you are viewing the same source version that was compiled; rebuild if necessary
