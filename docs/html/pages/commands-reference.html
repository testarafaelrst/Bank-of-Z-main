Commands Reference

This page provides a comprehensive reference for all CLI commands, scripts, and utilities used in Bank of Z workflows. It covers Zowe CLI operations, Git source control commands, environment setup verification, z/OS USS validation, and automation scripts used throughout the development lifecycle.

1. Overview

Bank of Z relies on a combination of command-line tools, shell scripts, and automation workflows to support development, build, and deployment activities across both local workstations and z/OS USS environments. This reference consolidates all commands into a single resource so developers can quickly locate the syntax, purpose, and context for each operation.

The primary tools referenced in this guide include:

  • Zowe CLI — Connects to z/OS systems and drives mainframe workflows from the developer workstation.
  • Git — Manages source code versioning and collaboration.
  • Node.js / npm / Java — Required runtime and build dependencies.
  • Workflow scripts — Shell scripts that orchestrate setup and pipeline execution.
  • Documentation scripts — Python utilities for managing documentation assets.

2. System Architecture

The diagram below illustrates how the local developer environment, Zowe CLI, and z/OS USS backend interact during a typical Bank of Z workflow. Commands issued locally are routed through z/OSMF or directly to USS, where build and deployment scripts execute.

graph TD A[Developer Workstation] -->|Zowe CLI Commands| B[z/OSMF API] A -->|Git Push / Pull| C[Remote Git Repository] A -->|Run setup-local.sh| D[Workflow Orchestration] B --> E[z/OS USS Environment] D -->|SSH / RSE API| E E -->|Run setup-common.sh| F[Environment Configuration] E -->|Run pipeline-remote.sh| G[Build and Deployment] G --> H[DBB Build Engine] H --> I[z/OS LPAR / Target System] C -->|Sync via GRUB Workflow| E

This architecture shows that all mainframe interactions are mediated either through the z/OSMF REST API (used by Zowe CLI) or through the RSE API plug-in. Local scripts such as setup-local.sh and pipeline-local.sh act as entry points that delegate the heavy lifting to their remote counterparts running on USS.

3. Zowe CLI Commands

Zowe CLI is the primary tool for connecting to z/OS systems and supporting the Bank of Z workflow. Install it once on your workstation and configure profiles to point at your target z/OS host.

The sequence below illustrates the typical Zowe CLI initialization flow, from installation through to verified connectivity.

sequenceDiagram participant Dev as Developer Workstation participant Zowe as Zowe CLI participant ZOSMF as z/OSMF on z/OS Dev->>Zowe: zowe plugins install @zowe/rse-api-for-zowe-cli Dev->>Zowe: zowe profiles create zosmf-profile myprofile Dev->>Zowe: zowe profiles set-default zosmf myprofile Dev->>Zowe: zowe zosmf check status Zowe->>ZOSMF: HTTP GET /zosmf/info ZOSMF-->>Zowe: 200 OK + system info Zowe-->>Dev: Connectivity verified

3.1 Verify Installation

BASH 
zowe --version

Displays the installed Zowe CLI version. Run this first to confirm that Zowe CLI is correctly installed before executing any other commands.

3.2 Install the RSE API Plug-in

BASH 
zowe plugins install @zowe/rse-api-for-zowe-cli

Installs the RSE API plugin required by the Bank of Z setup workflow. This plugin extends Zowe CLI with the ability to communicate with the RSE API service on z/OS.

3.3 Create a z/OSMF Profile

BASH 
zowe profiles create zosmf-profile myprofile \
  --host your-zos-host \
  --port 443 \
  --user your-userid

Creates a z/OSMF connection profile. Replace your-zos-host and your-userid with the values appropriate for your environment. The profile stores connection details so you do not need to supply them on every command.

3.4 Verify Connectivity

BASH 
zowe zosmf check status

Verifies connectivity to the configured z/OSMF instance. A successful response confirms that Zowe CLI can reach the mainframe.

3.5 List Available Profiles

BASH 
zowe profiles list zosmf

Displays all configured z/OSMF profiles. Useful when working with multiple environments (development, test, production).

3.6 Set a Default Profile

BASH 
zowe profiles set-default zosmf myprofile

Sets the default z/OSMF profile so that subsequent commands use it automatically without requiring an explicit --profile flag.

4. Git Commands

Git is used to manage source code changes and collaborate with other contributors. The following commands cover the standard development workflow for Bank of Z.

graph LR A[Clone Repository] --> B[Create Feature Branch] B --> C[Make Changes] C --> D[Stage Changes\ngit add .] D --> E[Commit Changes\ngit commit] E --> F[Push to Remote\ngit push] F --> G[Open Pull Request]

4.1 Clone a Repository

BASH 
git clone <repository-url>

Creates a local copy of a repository. Use this command when setting up a new development environment.

4.2 Create a Branch

BASH 
git checkout -b feature/my-change

Creates and switches to a new branch. Always develop on a feature branch rather than committing directly to main.

4.3 View Status

BASH 
git status

Displays modified, staged, and untracked files. Run this frequently to keep track of local changes before staging or committing.

4.4 Commit Changes

BASH 
git add .
git commit -m "Describe your change"

Stages all changes and creates a commit with a descriptive message. Write clear, concise commit messages that explain the purpose of the change.

4.5 Push Changes

BASH 
git push origin <branch-name>

Pushes committed changes to the remote repository so they are available for review and collaboration.

5. Setup Verification Commands

Before starting development or running workflows, verify that all required tools are installed and meet the minimum version requirements for Bank of Z.

5.1 Node.js

BASH 
node -v

Displays the installed Node.js version. Node.js is required for Zowe CLI and related tooling.

5.2 npm

BASH 
npm -v

Displays the installed npm version. npm is used to install JavaScript packages and manage project dependencies.

5.3 Git

BASH 
git --version

Displays the installed Git version. Confirms that Git is available before cloning repositories or running workflow scripts.

5.4 Java

BASH 
java -version

Displays the installed Java version. Java is required by the DBB build engine on z/OS USS.

6. USS Verification Commands

When working directly on the z/OS Unix System Services (USS) environment, use these commands to validate that the required tools and configurations are in place before running build or deployment activities.

graph TD A[Connect to USS] --> B{Verify Git} B -->|which git| C[Git Path Confirmed] B -->|git --version| D[Git Version Confirmed] A --> E{Verify DBB} E -->|ls DBB_HOME/lib| F[DBB Libraries Present] A --> G{Verify Java} G -->|JAVA_HOME/bin/java -version| H[Java Runtime Confirmed] C --> I[Environment Ready] D --> I F --> I H --> I

6.1 Verify Git Availability

BASH 
which git
git --version

Verifies that Git is installed and available in the USS environment. Both commands should return valid output before proceeding with any workflow that requires source code operations on USS.

6.2 Verify DBB Installation

BASH 
ls $DBB_HOME/lib

Verifies that the DBB installation path is accessible and that the required libraries are present. The $DBB_HOME environment variable must be set correctly in the USS shell profile.

6.3 Verify Java Configuration

BASH 
$JAVA_HOME/bin/java -version

Verifies that the configured Java runtime is available. This command explicitly uses the $JAVA_HOME variable, which ensures the correct Java version is used rather than any system default.

7. Workflow Scripts

Bank of Z uses a set of shell scripts to orchestrate setup and pipeline activities. These scripts serve as the entry points for automation and are designed to work in pairs — a local script on the developer workstation delegates to a remote script running on z/OS USS.

graph TD A[Developer Workstation] -->|Invokes| B[setup-local.sh] A -->|Invokes| C[pipeline-local.sh] B -->|Delegates to USS| D[setup-common.sh] C -->|Delegates to USS| E[pipeline-remote.sh] D --> F[Environment Configuration on USS] E --> G[Build Processing on USS] E --> H[Deployment Processing on USS]

The table below summarizes the purpose of each script:

Script Execution Environment Purpose
setup-local.sh Developer Workstation Initiates setup activities from the developer workstation
setup-common.sh z/OS USS Performs environment setup on z/OS USS
pipeline-local.sh Developer Workstation Initiates build and deployment processing
pipeline-remote.sh z/OS USS Runs build and deployment activities on z/OS USS

8. Zowe CLI Workflow Commands

The Zowe CLI workflow is the primary method for running the Bank of Z environment setup from a local workstation. It can be triggered either through a VS Code task or by running setup-local.sh directly from the terminal.

8.1 Run via VS Code Task

To run the workflow using the VS Code Command Palette:

  1. Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P).
  2. Run Tasks: Run Task.
  3. Select Setup Bank of Z Environment.

8.2 Run via Shell Script

BASH 
./setup-local.sh

Runs the setup workflow directly from the terminal. This is equivalent to the VS Code task and is suitable for environments where VS Code is not available.

For detailed workflow instructions, see the Zowe CLI Workflow documentation.

9. GRUB Workflow Commands

The GRUB workflow provides an alternative to the Zowe CLI workflow. It synchronizes local source changes to USS and then runs the Bank of Z setup or pipeline process on the mainframe.

sequenceDiagram participant Dev as Developer Workstation participant GRUB as GRUB Tool participant USS as z/OS USS Dev->>GRUB: Initiate GRUB Workflow GRUB->>USS: Synchronize local changes to USS USS-->>GRUB: Sync complete GRUB->>USS: Execute setup-common.sh or pipeline-remote.sh USS-->>GRUB: Execution complete GRUB-->>Dev: Workflow result returned

The GRUB workflow is particularly useful when working in environments with specific network configurations or when a direct Zowe CLI connection is not available. Refer to the GRUB Workflow documentation for environment-specific configuration and run procedures.

10. Documentation Scripts

In addition to development and deployment commands, Bank of Z includes Python utility scripts for managing documentation assets. These scripts are located in the docs/scripts/ directory.

10.1 convert_dita_to_md.py

Converts DITA XML files to Markdown format and generates a dynamic Table of Contents.

Requirements:

BASH 
pip3 install pyyaml

Usage:

BASH 
python3 scripts/convert_dita_to_md.py

What it does:

  1. Scans the Docs/ folder for DITA files.
  2. Converts DITA XML content to Markdown format.
  3. Creates an organized folder structure under docs/.
  4. Generates _data/toc.yml automatically.
  5. Creates index pages for each documentation section.

Example transformation:

BASH 
# Input (before running)
Docs/com.ibm.tutorials.doc/getting-started.dita

# Output (after running)
docs/tutorials/getting-started.md
docs/tutorials/index.md
_data/toc.yml  # updated automatically

10.2 Adding New Scripts

Place additional documentation management scripts in the docs/scripts/ directory and follow these conventions:

  • Use descriptive names: convert_dita_to_md.py
  • Use underscores for spaces: generate_pdf_docs.py
  • Include the .py extension for all Python scripts
  • Include a docstring explaining the purpose, usage instructions, requirements, and example output
