What is Bank of Z?

Bank of Z is an open-source banking application designed to demonstrate modern IBM Z development, build, deployment, and modernization practices. It provides a browser-based banking interface supporting common banking operations while integrating with IBM Z transaction-processing systems. Bank of Z bridges traditional enterprise technologies with modern development workflows to create a realistic environment for learning, demonstrations, and hands-on experimentation.

1. Overview

Bank of Z combines a hybrid application architecture with modern DevSecOps tooling to showcase how enterprise-grade applications can be developed and maintained on IBM Z. Customer requests are processed by either CICS or IMS Transaction Manager (IMS TM), both sharing common banking data stored in Db2 for z/OS.

The project is intended for:

  • Educational purposes – Learn IBM Z development workflows in a realistic setting
  • Demonstration purposes – Showcase enterprise application capabilities
  • Proof-of-concept purposes – Evaluate build, deployment, and modernization approaches

1.1 What You Can Learn

Bank of Z provides guided scenarios that demonstrate common IBM Z development and modernization activities, including:

2. System Architecture

Bank of Z uses a hybrid architecture that reflects how real-world IBM Z enterprise applications are structured. A browser-based front end communicates with back-end services via a z/OS Connect API layer, which routes requests to either a CICS or IMS transaction processing environment. Both paths share a common Db2 for z/OS data store.

The diagram below illustrates the high-level system architecture and how the components relate to one another:

graph TD A[Browser / End User] -->|HTTP Request| B[Web Front End\nbank-frontend-vanilla.war] B -->|REST API Call| C[z/OS Connect API Layer\napi.war] C -->|CICS Request| D[CICS Transaction Manager\nCICSBOZ Region] C -->|IMS Request| E[IMS Transaction Manager\nIMS TM] D -->|SQL Query| F[Db2 for z/OS\nShared Banking Data] E -->|DL/I Call| F E -->|IMS DB| G[IMS Database\nIMS DB]

The architecture highlights several key design principles:

  • Hybrid transaction processing – CICS and IMS TM operate in parallel, each handling a subset of banking operations
  • Shared data layer – Db2 for z/OS serves as the common data store, accessible from both CICS and IMS paths
  • Modern API exposure – z/OS Connect acts as the API gateway, exposing back-end transactions as RESTful services consumed by the web front end

3. Purpose and Use Cases

3.1 Primary Purpose

Bank of Z helps demonstrate how enterprise applications can be developed, built, deployed, and maintained on IBM Z using modern development practices and tooling. Rather than working with abstract examples, users interact with a fully functional banking application that exercises real IBM Z components.

3.2 Use Cases

The project supports a wide range of use cases:

  • Learn IBM Z development workflows – Understand how source code flows from development through build and deployment on z/OS
  • Explore application modernization approaches – See how legacy transaction systems can be exposed via modern REST APIs
  • Demonstrate enterprise application capabilities – Showcase IBM Z technologies to stakeholders and teams
  • Evaluate build and deployment automation – Use IBM Dependency Based Build (DBB) and Wazi Deploy in a realistic context
  • Experiment with IBM Z development tools – Work hands-on with tools such as Zowe CLI, zConfig, and ZCodeScan
  • Extend and customize a sample banking application – Add features or modify existing behavior to suit learning or demonstration objectives

5. Key Technologies

Bank of Z integrates a broad set of IBM Z technologies across the full development lifecycle:

5.1 Transaction Processing

  • CICS – Handles customer-facing banking transactions (account inquiry, transfers, customer updates)
  • IMS TM – Provides an alternative transaction processing path for a subset of banking operations
  • Db2 for z/OS – Shared relational database for all banking data (customers, accounts, transaction history)
  • IMS DB – Hierarchical database used by the IMS transaction path

5.2 Modern Integration and Tooling

  • z/OS Connect – Exposes CICS and IMS transactions as RESTful APIs consumed by the web front end
  • IBM Dependency Based Build (DBB) – Automates the build of COBOL, PL/I, Assembler, and BMS source files
  • Wazi Deploy – Manages automated deployment of build outputs to CICS, Db2, and z/OS Connect
  • zConfig – Provisions and configures z/OS middleware (CICS regions, z/OS Connect servers)
  • Zowe CLI – Provides remote access to z/OS resources from a local development workstation
  • ZCodeScan – Performs static code analysis on z/OS application source

5.3 Application Components

The application ships with programs written in multiple languages to reflect the diversity of a real IBM Z application:

Language Usage
COBOL CICS transaction programs, IMS batch and transaction programs
PL/I IMS login program (IBLOGIN)
Assembler IMS DBD and PSB definitions
BMS CICS map definitions for screen layouts
Java/WAR Web front end and z/OS Connect API layer

6. Application Flow

The following sequence diagram illustrates how a typical banking request flows through the Bank of Z system — from the browser to the back-end transaction processors and back:

sequenceDiagram actor User as End User (Browser) participant FE as Web Front End participant API as z/OS Connect API participant CICS as CICS Transaction Manager participant IMS as IMS Transaction Manager participant DB2 as Db2 for z/OS User->>FE: Submit banking request (e.g., Account Inquiry) FE->>API: REST API call (HTTP/JSON) alt CICS path API->>CICS: Invoke CICS transaction CICS->>DB2: SQL query / update DB2-->>CICS: Result set CICS-->>API: Transaction response else IMS path API->>IMS: Invoke IMS transaction IMS->>DB2: DL/I call or SQL query DB2-->>IMS: Result set IMS-->>API: Transaction response end API-->>FE: JSON response FE-->>User: Display result

This hybrid routing is a defining characteristic of Bank of Z — the same web interface and API layer can exercise both CICS and IMS back ends, allowing users to study and compare both transaction processing environments within a single application.

7. Development and Deployment Workflow

Bank of Z ships with a fully automated setup and pipeline simulation environment on z/OS Unix System Services (USS). The setup process configures all required middleware and deploys the application in a repeatable manner.

7.1 Setup and Installation Flow

graph TD A[Clone Repository on z/OS USS] --> B[Edit config.yaml] B --> C[Validate Prerequisites\nsetup-common.sh validate-prereqs] C --> D[Provision Environment\nsetup-common.sh environment] D --> D1[Create Db2 Tables] D --> D2[Create CICS Region via zConfig] D --> D3[Create z/OS Connect Server] D1 & D2 & D3 --> E[Build and Deploy\nsetup-common.sh install-bank-of-z] E --> E1[DBB Full Build\n72 source files] E1 --> E2[Wazi Deploy\nDeploy to CICS + Db2 + z/OS Connect] E2 --> E3[Populate Db2 Tables] E3 --> F[Access Web Front End\nhttp://hostname:9080/bank-frontend-vanilla]

7.2 Sample Setup Commands

Setting up the Bank of Z environment involves a sequence of shell script invocations on z/OS USS:

BASH 
# Step 1: Clone and navigate to the repository
export BANK_OF_Z_WORK_DIR=/usr/local/sandboxes/bank-of-z
mkdir -p $BANK_OF_Z_WORK_DIR
cd $BANK_OF_Z_WORK_DIR
git clone https://github.com/ibm/Bank-of-Z.git
cd Bank-of-Z

# Step 2: Edit configuration for your environment
vi .setup/config/config.yaml

# Step 3: Validate prerequisites (DBB, ZOAU, zConfig, Wazi Deploy)
.setup/setup-common.sh validate-prereqs

# Step 4: Provision the middleware environment
.setup/setup-common.sh environment

# Step 5: Build and deploy the application
.setup/setup-common.sh install-bank-of-z

7.3 Sample Configuration

The central configuration file controls workspace paths, application identity, and tool locations:

YAML 
# Workspace location on z/OS USS
sandbox:
  path: /usr/local/sandboxes/bank-of-z

# Application identity
app:
  base_name: BANKZ    # Dataset prefix (max 8 chars)
  short_name: BOZ     # Short identifier (max 4 chars)
  zos_version: V0R1M0 # Version for dataset naming

# DBB configuration
dbb:
  dbb_home: /usr/lpp/IBM/dbb
  java_home: /usr/lpp/java/java21/current_64

8. Repository Structure

The Bank of Z repository is organized to separate application source code from build, deployment, and setup automation:

CODE 
Bank-of-Z/
├── src/
│   ├── base/
│   │   ├── cics/
│   │   │   ├── bms/        # CICS BMS map definitions
│   │   │   └── cobol/      # CICS COBOL transaction programs
│   │   └── ims/
│   │       ├── cobol/      # IMS COBOL programs
│   │       ├── pli/        # IMS PL/I programs
│   │       ├── DBD/        # IMS Database Definitions (Assembler)
│   │       └── PSB/        # IMS Program Specification Blocks (Assembler)
│   ├── api/                # z/OS Connect API definitions (OpenAPI)
│   └── frontend/           # Web front-end source
├── .setup/
│   ├── config/
│   │   └── config.yaml     # Central configuration file
│   ├── setup/              # Environment provisioning scripts
│   ├── tasks/              # Build and deploy task scripts
│   └── deploy/             # Wazi Deploy configuration
├── zcodescan/              # ZCodeScan rules
└── docs/                   # Documentation source
