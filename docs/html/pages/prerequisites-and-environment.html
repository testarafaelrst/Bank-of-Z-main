Prerequisites & Environment Configuration

Bank of Z is a self-contained sample hybrid banking application that demonstrates modern IBM Z development, deployment, and DevSecOps practices. Before deploying Bank of Z, your environment must meet a set of platform, tooling, access, and configuration requirements. This page describes all system requirements, prerequisites, and environment configuration steps needed to prepare your z/OS environment and local workstation for a successful Bank of Z installation.

Complete every section on this page before starting any of the getting-started deployment tutorials.

1. System Architecture Overview

Bank of Z integrates a layered set of IBM Z middleware components, build and deploy tooling, and local development tools. Understanding how these layers relate helps you identify which prerequisites apply to your role and environment.

The diagram below illustrates the high-level system architecture and the relationship between the developer workstation, USS tooling layer, and the z/OS middleware stack.

graph TD subgraph Workstation["👩‍💻 Developer Workstation"] IDE["IDE / Bob IDE"] ZoweCLI["Zowe CLI"] GRUB["GRUB"] end subgraph USS["z/OS UNIX System Services (USS)"] Git["Git"] Java["IBM Java 21"] Python["IBM Python SDK 3.14"] DBB["IBM DBB 3.0.5"] ZOAU["Z Open Automation Utilities (ZOAU)"] zconfig["zconfig 0.7.0"] WaziDeploy["Wazi Deploy 3.0.7.3"] ZCodeScan["ZCodeScan 1.0.2"] Gradle["Gradle 9.5.1"] CRB["CICS TS Resource Builder"] end subgraph ZOS["z/OS Middleware"] CICS["CICS TS 6.3"] IMS["IMS TM + IMS DB V15"] DB2["Db2 for z/OS V13"] MQ["IBM MQ"] ZOSConnect["z/OS Connect EE 3.0.101"] end subgraph Config["Configuration"] ConfigYAML[".setup/config/config.yaml"] end Workstation -->|"SSH / Zowe / GRUB"| USS USS -->|"Provisions & Deploys"| ZOS ConfigYAML -->|"Drives"| USS zconfig -->|"Provisions CICS/IMS/z/OS Connect"| ZOS DBB -->|"Builds source"| ZOS WaziDeploy -->|"Deploys artifacts"| ZOS

The developer workstation communicates with z/OS USS through SSH, Zowe CLI, or GRUB. The USS tooling layer drives the build and deployment pipeline, and all paths and versions are centrally controlled by .setup/config/config.yaml.

2. Installation Workflow

The Bank of Z installation process follows a defined sequence of stages. Each stage has prerequisites that must be satisfied before moving to the next.

sequenceDiagram participant Admin as System Administrator participant Dev as Developer participant USS as z/OS USS participant MW as z/OS Middleware Admin->>USS: Install Java, Python, DBB, ZOAU, zconfig, Wazi Deploy Admin->>MW: Provision Db2 subsystem (DBD1), configure RACF Dev->>Dev: Configure .setup/config/config.yaml Dev->>USS: Run .setup/setup-common.sh validate-prereqs USS-->>Dev: Validation results Dev->>USS: Run grant-perm-user.sh (non-IBMUSER only) Dev->>USS: Set IMS_USER, IMS_PASSWORD, CICS_USER, CICS_PASSWORD Dev->>USS: Create ZCodeScan config file (ISO8859-1) Dev->>USS: Run environment setup phase USS->>MW: zconfig provisions CICS, IMS, z/OS Connect USS-->>Dev: Environment ready Dev->>USS: Build and deploy Bank of Z

This sequence ensures that administrator-level infrastructure is in place before the developer begins configuration and setup tasks.

4. z/OS Platform Requirements

4.1 Middleware Components

The target z/OS environment must include the following platform components. Contact your system administrator if any of these are not available.

Component Minimum Version
z/OS 3.1
CICS TS 6.3
Db2 for z/OS V13
IMS Transaction Manager (IMS TM) V15
IMS Database V15
z/OS Connect Enterprise Edition 3.0.101
IBM MQ Supported release

Important: A pre-existing Db2 subsystem with subsystem ID DBD1 is required. The setup scripts create the required Db2 database objects within this subsystem but do not create the subsystem itself. IMS, CICS, and z/OS Connect runtime instances are provisioned automatically by zconfig during the environment setup phase.

4.2 USS Access Requirements

Requirement Details
USS write access Your user ID must have write permission on the sandbox path configured in config.yaml
Git available in PATH Required for setup scripts to clone the DBB accelerators repository from GitHub
Network connectivity to github.com The environment phase clones https://github.com/IBM/dbb.git from USS

6. Access and Security Requirements

Ensure the following access is in place before proceeding. Contact your system administrator if you do not have the required access.

Access Requirement Description
TSO user ID and password Required for authentication and system access
USS access Required to access z/OS UNIX System Services resources
Dataset creation permissions Permission to create and modify datasets
Deployment permissions Permission to deploy application resources
Middleware access Access to CICS, IMS, Db2, IBM MQ, and z/OS Connect, as applicable

Appropriate security definitions must also be configured in RACF or an equivalent security manager before deployment. The required definitions depend on your target environment. Contact your system administrator if you are unsure what is required.

Note: Access to z/OS environments, middleware, USS directories, and dataset resources is typically provisioned by your system administrator. If you do not have the required access, contact your administrator before proceeding.

7. External Tools Requirements

7.1 Python Libraries

Install the required Python libraries on z/OS USS by running the following commands:

BASH 
pip install pyyaml
pip install jinja2

7.2 Gradle

Download the latest supported Gradle binary distribution from the Gradle releases page.

After downloading the archive, install Gradle on z/OS USS by running the following commands:

BASH 
jar xf gradle-9.5.1-bin.zip
chmod +x gradle-9.5.1/bin/gradle
chtag -tc UTF-8 gradle-9.5.1/bin/gradle

Note: Update the version number in the commands if you download a different Gradle release.

8. Validate Prerequisites

After your system administrator has confirmed the above tooling is in place, run the prerequisite validation script from USS to confirm that all build and deploy tooling is correctly installed:

BASH 
.setup/setup-common.sh validate-prereqs

This script checks versions of DBB, ZOAU, zconfig, and Wazi Deploy, and verifies Git availability and network connectivity to GitHub. Resolve any reported issues before proceeding to environment configuration.

9. Environment Configuration

9.1 Configure the Application

Edit .setup/config/config.yaml in your local clone of the repository. This file controls all paths, environment settings, and middleware configuration used during setup, build, and deployment.

Update the values in the global section to match your environment. Unless otherwise noted, remaining configuration values use template references ({{section.field}}) and do not require modification.

YAML 
# Global properties
# - Shared by middleware/tools
# - Subject to change with middleware/tools updates
global:

  # Sandbox
  sandbox_root: "/usr/local/sandboxes"

  # Application
  app_base_name: "BANKZ"
  app_hlq: "{{ global.app_base_name }}"
  app_short_name: "BOZ" # Maximum 3 characters
  app_version: "0"
  app_release: "1"
  app_modification: "0"

  # Tools
  java_home: "{{ sandbox.root }}/tools/J21.0_64"
  python_home: "/usr/lpp/IBM/cyp/v3r14/pyz"
  zoau_home: "/usr/lpp/IBM/zoau"
  zconfig_home: "{{ global.sandbox_root }}/tools/zconfig"
  zcb_home: "{{ global.sandbox_root }}/tools/zrb/cics-resource-builder-1.0.6"
  dbb_home: "{{ global.sandbox_root }}/tools/dbb"
  gradle_home: "{{ global.sandbox_root }}/tools/gradle-9.5.1"
  zcodescan_home: "/global/opt/pyenv/akf"
  wazideploy_home: "/global/opt/pyenv/gdp"
  zosconnect_home: "/usr/lpp/IBM/zosconnect"
  liberty_home: "/usr/lpp/liberty_zos/25.0.0.9"

  # z/OS System
  zos_admin_user: "IBMUSER"
  zos_current_user: "${ZOS_CURRENT_USER}"
  zos_ca_label: "VSICA"
  zos_keyring: "BOZRING"
  sys_proclib: "SYS1.PROCLIB"
  tcpip_hlq: "TCPIP"

  # GUI
  zosconnect_http_port: 9080
  zosconnect_https_port: 9444
  zosconnect_task_user: "{{ global.zos_admin_user }}"

  # Frontend
  frontend_http_port: 9081
  frontend_https_port: 9445
  frontend_task_user: "{{ global.zos_admin_user }}"

  # CICS
  cics_hlq: "CICSTS63"
  cics_uss_dir: "/usr/lpp/cicsts/cicsts63"
  cics_sec: "YES"

  # IMS
  ims_disabled: "false"
  ims_sys_hlq: "IMSV15"
  ims_java_dir: "/usr/lpp/ims/imsjava"
  ims_datastore: "IMS2"
  ims_dfsplex: "PLEX2"

  # DB2
  db2_hlq: "DB2V13"
  db2_dsntep: "DSNTEP13"
  db2_ssid: "DBD1"
  db2_runlib: "{{ global.db2_ssid }}.RUNLIB.LOAD"
  db2_sqlid: "{{ global.zos_current_user }}"
  db2_java_dir: "/usr/lpp/db2d10"
  db2_grants:
  - "CICSUSER"

The config.yaml file supports variable expansion using {{section.field}} syntax for template references, and ${ENV_VAR} syntax for environment variable references. For a complete field description of every configuration property, see the Configuration Reference.

9.2 Configuration Key Fields Reference

The following table summarizes the most critical fields you must review and update in the global section:

Field Description Constraint
sandbox_root Root USS directory for all components Must be an absolute path; user must have write access
app_base_name Dataset high-level qualifier Maximum 8 characters, alphanumeric only
app_short_name Short application identifier used in CICS/IMS names Maximum 3 characters
java_home Path to IBM Java 21 installation Must point to a valid Java 21 installation
python_home Path to IBM Python SDK 3.14 Must point to a valid Python installation
dbb_home Path to IBM DBB installation Must point to DBB 3.0.5 or later
zoau_home Path to ZOAU installation Must point to ZOAU 1.4.1.0 or later
db2_ssid Db2 subsystem ID Must match an existing Db2 subsystem (DBD1 by default)

9.3 Grant Permissions (Non-IBMUSER Accounts Only)

If you are not using the IBMUSER user ID, grant your user ID permission to create Db2 database objects before running the environment setup phase.

Run the following command as an administrator, replacing MYUSER with your user ID:

BASH 
.setup/setup/grant-perm-user.sh MYUSER

9.4 Set IMS and CICS Credentials

Before running the setup scripts, set the following environment variables on USS:

Variable Description
IMS_USER IMS user ID
IMS_PASSWORD IMS password
CICS_USER CICS user ID
CICS_PASSWORD CICS password

Set these variables as shown in the following example:

BASH 
export IMS_USER=<your_ims_user>
export IMS_PASSWORD=<your_ims_password>

export CICS_USER=<your_cics_user>
export CICS_PASSWORD=<your_cics_password>

9.5 Create the ZCodeScan Configuration File

The static scan stage requires a ZCodeScan configuration file. This file must be created manually and encoded in ISO8859-1 because ZCodeScan cannot read files saved in IBM-1047 or UTF-8.

Create ~/zcs_config_file.yml, or the path specified by zcodescan.config_file in config.yaml:

YAML 
license_server:
  url: https://127.0.0.1:8195
  user: MYUSER
  password: MY_PASSWORD
  verify: false

Note: The password is automatically encrypted after the first scan. You only need to provide it in plain text on first use.

11. Configuration Validation

The setup scripts automatically validate config.yaml before executing any stage. The following checks are performed:

Validation Check Rule
Required fields present sandbox.path, app.base_name, app.short_name, dbb.dbb_home, dbb.java_home must all be set
Absolute paths All path values must begin with / and must not contain trailing slashes
Variable resolution All {{section.field}} and ${ENV_VAR} references must resolve without circular dependencies
Character limits app_base_name ≤ 8 characters; app_short_name ≤ 3 characters

11.1 Common Configuration Errors

Configuration file not found:

BASH 
# Verify the file exists and you are in the correct directory
ls -la .setup/config/config.yaml
pwd

Variable reference cannot be resolved:

YAML 
# Incorrect: references a non-existent section
dbb:
  build_dir: ${workspace.path}/build

# Correct: use the right section name
dbb:
  build_dir: ${sandbox.path}/build

Invalid path format:

YAML 
# Incorrect: relative path
sandbox:
  path: sandboxes/bank-of-z

# Correct: absolute path
sandbox:
  path: /usr/local/sandboxes/bank-of-z
