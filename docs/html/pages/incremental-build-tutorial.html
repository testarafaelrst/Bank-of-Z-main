Tutorial: Incremental Build

1. Overview

This tutorial demonstrates how to perform an incremental build after making a source code change in the Bank of Z application. You will update a COBOL program, push the change to a Git branch, pull it to z/OS USS, and use the Bank of Z incremental build workflow to detect and build only the affected application component.

The incremental build process leverages IBM Dependency Based Build (DBB) to intelligently identify which files have changed and ensures that only the impacted programs are recompiled — saving time and reducing unnecessary build overhead.

Prerequisites: Before starting this tutorial, ensure you have:

  • Completed the Deploy Bank of Z tutorial
  • Successfully built and deployed Bank of Z
  • A working Bank of Z development environment
  • Access to the Bank of Z Git repository and z/OS USS environment

By completing this tutorial, you will learn how to:

  • Make a change to a COBOL program
  • Commit and push the change to a Git branch
  • Pull the latest changes to z/OS USS
  • Run an incremental build using pipeline-remote.sh
  • Verify that DBB detects the changed COBOL source file
  • Confirm that the affected program is included in the build
  • Optionally verify the updated behavior in CICS

2. System Architecture

The following diagram illustrates how the Bank of Z incremental build system is structured, showing the key environments and components involved in moving a source code change from a developer’s workstation through to a deployed application on z/OS.

graph TD A[Developer Workstation] -->|Edit COBOL Source| B[Local Git Repository] B -->|git commit + git push| C[Remote Git Repository] C -->|git pull| D[z/OS USS Environment] D -->|Execute pipeline-remote.sh| E[DBB - Dependency Based Build] E -->|Detect Changed Files| F{Changed Files?} F -->|Yes - BNKMENU.cbl| G[Incremental Compile] F -->|No Changes| H[Skip Build] G -->|Generate Load Module| I[CICS Runtime] I -->|Serve Updated Application| J[End User / CICS Terminal]

The incremental build pipeline spans two primary environments:

  • Development Environment — where the developer edits COBOL source files and manages version control using Git.
  • z/OS USS Environment — where the source is pulled and DBB executes the incremental build, compiling only the changed programs and deploying updated load modules to CICS.

3. Part 1: Make and Push the COBOL Change

In this part, you modify the BNKMENU.cbl COBOL source file on your local development machine and push the change to the remote Git repository so it is available for the z/OS build environment.

3.1 Update the BNKMENU.cbl Program

Open the BNKMENU.cbl file in your editor and locate the invalid-key message string. Update the message text to reflect your desired change.

Example — Before:

COBOL 
MOVE 'INVALID KEY ENTERED'
    TO WS-ERROR-MESSAGE

Example — After:

COBOL 
MOVE 'KEY NOT RECOGNIZED - PLEASE RETRY'
    TO WS-ERROR-MESSAGE

3.2 Confirm the Correct Git Branch

Before committing, verify you are working on the correct feature branch.

BASH 
git branch

Expected output:

CODE 
* feature/bnkmenu-message-update
  main

3.3 Commit the Source Change

Stage and commit the updated COBOL source file.

BASH 
git add src/BNKMENU.cbl
git commit -m "Update invalid-key message in BNKMENU"

3.4 Push the Change to the Remote Repository

Push your branch to the remote Git repository.

BASH 
git push origin feature/bnkmenu-message-update

The following sequence diagram illustrates the flow of actions in Part 1:

sequenceDiagram Developer->>Local Repository: Edit BNKMENU.cbl Developer->>Local Repository: git add + git commit Local Repository-->>Developer: Commit confirmed Developer->>Remote Repository: git push Remote Repository-->>Developer: Push accepted

4. Part 2: Run and Verify the Incremental Build

With the change pushed to the remote repository, you now connect to the z/OS USS environment, pull the latest source, and run the incremental build.

4.1 Connect to the z/OS USS Environment

Use SSH to connect to your z/OS USS host.

BASH 
ssh user@your-zos-host

4.2 Confirm the Correct Git Branch

Once connected, navigate to the Bank of Z project directory and confirm you are on the correct branch.

BASH 
cd /u/bankofz/project
git branch

Expected output:

CODE 
* feature/bnkmenu-message-update
  main

4.3 Pull the Latest Source Changes

Pull the latest source changes from the remote repository.

BASH 
git pull origin feature/bnkmenu-message-update

Expected output:

CODE 
remote: Enumerating objects: 5, done.
Updating abc1234..def5678
Fast-forward
 src/BNKMENU.cbl | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)

4.4 Run the Incremental Build

Execute the pipeline-remote.sh script to trigger the incremental build. DBB will analyse the repository, detect the changed file, and compile only the affected programs.

BASH 
./pipeline-remote.sh

4.5 Verify DBB Detects the Changed File

Review the build output to confirm that DBB has identified BNKMENU.cbl as a changed source file.

CODE 
[INFO] Scanning repository for changes...
[INFO] Changed file detected: src/BNKMENU.cbl
[INFO] Resolving dependencies for BNKMENU...
[INFO] Adding BNKMENU to the build list.

4.6 Confirm BNKMENU Is Included in the Compiled Programs

The build log should confirm that BNKMENU was compiled as part of this incremental build run.

CODE 
[INFO] Compiling: BNKMENU
[INFO] COBOL compile step completed successfully.
[INFO] Link-edit step completed successfully.
[INFO] Load module written to: USER.BANKOFZ.LOAD(BNKMENU)
[INFO] Incremental build completed. Programs compiled: 1

4.7 (Optional) Validate the Updated Message in CICS

After the build completes and the updated load module is deployed, log in to your CICS environment and navigate to the BNKMENU transaction to confirm that the new invalid-key message is displayed correctly.

The following sequence diagram summarises the complete Part 2 flow:

sequenceDiagram Developer->>z/OS USS: SSH connection Developer->>z/OS USS: git pull z/OS USS-->>Remote Repository: Fetch latest changes Remote Repository-->>z/OS USS: Updated BNKMENU.cbl Developer->>z/OS USS: Execute pipeline-remote.sh z/OS USS->>DBB: Trigger incremental build DBB->>DBB: Detect changed files DBB-->>z/OS USS: BNKMENU.cbl identified as changed DBB->>z/OS USS: Compile BNKMENU z/OS USS->>CICS: Deploy updated load module CICS-->>Developer: Updated application available

5. Outcome

After completing this tutorial, you have:

  • Made a targeted source code change to BNKMENU.cbl
  • Committed and pushed the change using Git version control
  • Pulled the updated source to z/OS USS
  • Executed an incremental build using pipeline-remote.sh
  • Verified that DBB correctly identified and compiled only the changed program
  • Optionally confirmed the updated application behaviour in CICS

You now understand how source changes travel from a development environment through Git version control to z/OS USS, and how the Bank of Z incremental build process uses DBB to efficiently detect and build only the affected application components — without requiring a full rebuild of the entire application.
