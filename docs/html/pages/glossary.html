Glossary

This glossary defines common terms, acronyms, and technologies used throughout the Bank of Z documentation. It serves as a centralized reference for developers, operators, and architects working with the Bank of Z hybrid banking application on IBM Z.

1. Overview

Bank of Z is a sample hybrid banking application that demonstrates modern z/OS application development, integration, build, deployment, and operational workflows. Understanding the terminology used across its components is essential for navigating the documentation effectively.

The glossary covers the following categories:

  • Core Technologies — foundational IBM Z platforms and middleware
  • Development Tools — IDEs, CLIs, and build frameworks
  • Application Components — services, routing mechanisms, and databases
  • Workflows and Processes — build, deploy, and operational automation concepts

3. Core Application Terms

3.1 Bank of Z

Bank of Z is a sample hybrid banking application that demonstrates modern z/OS application development, integration, build, deployment, and operational workflows. It serves as a reference implementation showcasing how IBM Z technologies can be combined into a unified banking experience.

3.2 Bank of Q

Bank of Q is a sample external banking system used to demonstrate inter-application communication and money transfer scenarios through IBM MQ. It acts as a simulated external banking partner.

3.3 Hybrid Architecture

A Hybrid Architecture is an application architecture that integrates multiple transaction-processing environments and technologies into a unified user experience. In Bank of Z, requests are processed through either CICS or IMS TM while sharing common services and data resources.

graph LR A[Unified User Interface] --> B[z/OS Connect REST Layer] B --> C[CICS Environment] B --> D[IMS TM Environment] C --> E[Shared Db2 Data Layer] D --> E C --> F[IBM MQ] D --> F F --> G[Bank of Q]

3.4 Customer Routing

Customer Routing is the Bank of Z mechanism that routes requests to either CICS or IMS TM based on the customer identifier pattern:

Customer ID Prefix Routed To
C CICS Transaction Manager
I IMS TM Transaction Manager

Example customer identifiers:

CODE 
C000001   → routed to CICS
I000042   → routed to IMS TM

4. IBM Z Platform Technologies

4.1 z/OS

The underlying operating system for all Bank of Z server-side components, providing reliability, security, and scalability.

4.2 USS (UNIX System Services)

USS stands for UNIX System Services — the POSIX-compliant environment within z/OS used to host source code, scripts, build artifacts, and application assets. USS provides a familiar Unix-like interface for developers working on z/OS.

4.3 CICS

CICS (Customer Information Control System) is an IBM transaction-processing system used to execute online business transactions. In Bank of Z, customers with identifiers beginning with C are routed to CICS transactions.

4.4 IMS TM

IMS TM (IBM Information Management System Transaction Manager) is a transaction-processing environment used by Bank of Z. Customers with identifiers beginning with I are routed to IMS TM transactions.

4.5 IMS DB

IMS DB (IBM Information Management System Database) is a hierarchical database used by the IMS processing path within Bank of Z.

4.6 Db2

Db2 refers to IBM Db2 for z/OS — a relational database used to store customer, account, and transaction information.

4.7 Account History Db2 Database

The Account History Db2 Database is a Db2 database used by Bank of Z to store historical account and transaction information for inquiry and reporting functions.

4.8 IBM MQ

IBM MQ is IBM messaging middleware used for asynchronous communication between applications and external systems. In Bank of Z, it facilitates communication with Bank of Q.

4.9 z/OS Connect

z/OS Connect is an API framework that enables REST-based access to z/OS applications and services. In Bank of Z, it provides the interface between the web application and the CICS and IMS transaction environments.

4.10 JVM

JVM (Java Virtual Machine) is the runtime environment used to execute Java applications and services on z/OS.

4.11 ZOAU

ZOAU (IBM Z Open Automation Utilities) is a collection of utilities and APIs used to automate z/OS administration and development tasks.

5. Programming Languages and Data Structures

5.1 COBOL

COBOL (Common Business-Oriented Language) is the primary programming language used for the Bank of Z business logic. It is widely used in enterprise transaction processing.

Example COBOL data structure:

COBOL 
01 ACCOUNT-RECORD.
   05 ACCOUNT-ID       PIC X(10).
   05 CUSTOMER-ID      PIC X(10).
   05 ACCOUNT-BALANCE  PIC S9(13)V99 COMP-3.
   05 ACCOUNT-TYPE     PIC X(5).

5.2 Copybook

A Copybook is a reusable source file containing data structure definitions shared across COBOL programs. Copybooks promote consistency and reduce duplication across the codebase.

Example copybook usage in COBOL:

COBOL 
COPY ACCTCOPY.

5.3 BMS

BMS (Basic Mapping Support) is a CICS facility used to define terminal screen layouts and user interactions. It describes the structure of 3270 terminal screens used in CICS applications.

6. Development Tools

6.1 VS Code

VS Code (Visual Studio Code) is a development environment commonly used to develop, build, and manage Bank of Z assets. It integrates with Zowe CLI, DBB, and other z/OS tooling.

6.2 Bob IDE

Bob IDE (IBM Premium Bob for Z) is an integrated development environment that supports IBM Z application development workflows.

6.3 Git

Git is a distributed version control system used to manage source code and support collaborative development in Bank of Z projects.

6.4 Zowe CLI

Zowe CLI is a command-line interface used to interact with z/OS systems, services, datasets, USS files, and development workflows.

Example Zowe CLI command to list datasets:

BASH 
zowe files list ds "USER.BANK.OF.Z.*"

6.5 RSE API

RSE API (Remote System Explorer API) is a service used by Zowe CLI and development tools to interact with z/OS resources.

6.6 ZCodeScan

ZCodeScan is a static analysis tool used to analyze source code quality and identify potential issues in z/OS application code.

7. Build and Deployment Frameworks

7.1 DBB

DBB (IBM Dependency Based Build) is a build framework used to compile, link, and manage z/OS application builds. It tracks dependencies between source files to enable incremental builds.

7.2 zBuilder

zBuilder is a build framework used with DBB to automate compilation, linking, and build orchestration for z/OS applications.

Example zBuilder build invocation:

BASH 
groovyz dbbBuild.groovy --application BankOfZ --sourceDir /u/boz/src

7.3 Wazi Deploy

Wazi Deploy is IBM deployment automation tooling used to deploy application artifacts and configuration changes to z/OS environments.

7.4 zconfig

zconfig (z/OS Middleware Configuration Tool) is a command-line tool used to configure and create artifacts for CICS Transaction Server for z/OS (CICS TS), Db2 for z/OS (Db2), Information Management System (IMS), and z/OS Connect. It introduces configuration as code to z/OS middleware.

Example zconfig usage:

BASH 
zconfig apply --config cics-config.yaml --env ode-dev

8. Workflows and Environments

8.1 Workflow

A Workflow is a defined development process used to build, deploy, test, and validate application changes. Bank of Z supports the following workflows:

Workflow Description
VS Code Workflow Developer uses VS Code with Zowe extensions to edit, build, and deploy from a local workstation
GRUB Workflow Developer syncs local changes to z/OS USS and runs build processes without committing every change

8.2 GRUB

GRUB (Git Remote User Build) is a workflow that synchronizes local changes to z/OS USS and runs setup and build processes without requiring commits for every change. It enables a faster inner-loop development experience.

8.3 ODE

ODE (On-Demand Environment) is a preconfigured development and testing environment used to provision and run Bank of Z components. It enables developers to stand up isolated instances for testing.

8.4 API

API (Application Programming Interface) is a defined interface that enables applications and services to communicate with each other. In Bank of Z, APIs are exposed via z/OS Connect as RESTful endpoints.

Example REST API call to Bank of Z:

BASH 
curl -X GET https://<zos-connect-host>:<port>/bankofz/accounts/C000001 \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json"
