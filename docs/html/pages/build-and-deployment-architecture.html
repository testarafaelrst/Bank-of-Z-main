Build & Deployment Architecture

Bank of Z employs a structured, automated build and deployment pipeline that transforms source code into deployable artifacts and provisions them across CICS and IMS runtime environments. IBM Dependency Based Build (DBB), Wazi Deploy, zconfig, and the z/OS Connect CLI work together to automate the full lifecycle — from compilation through runtime provisioning — enabling both initial deployments and iterative, incremental updates.

1. Overview

The Bank of Z build and deployment architecture is designed to support enterprise-grade mainframe application delivery. The pipeline handles a diverse set of source assets — including COBOL, PL/I, Assembler, BMS maps, Db2 definitions, Java source, and z/OS Connect API definitions — and produces fully packaged, deployment-ready artifacts.

Two primary build workflows are supported:

  • Full Build — Compiles and packages the entire application. Used for initial installations or when infrastructure changes require a complete redeployment.
  • Incremental Build — Rebuilds and deploys only the components affected by source changes. Used for day-to-day development, enhancements, and defect fixes.

Once built, artifacts are deployed to either a CICS or IMS runtime environment (or both), with z/OS Connect APIs configured to route inbound requests to the appropriate transaction-processing backend.

The following diagram illustrates the high-level system architecture, showing how the major tooling components interact across the build and deployment lifecycle.

This architecture ensures a clean separation of concerns: IBM DBB handles compilation and dependency resolution, Wazi Deploy manages artifact packaging and installation, zconfig provisions the underlying runtime environments, and the z/OS Connect CLI exposes transaction endpoints as RESTful APIs.

3. Build Pipeline

3.1 Source Assets

IBM Dependency Based Build (DBB) ingests the full range of Bank of Z source assets stored in the repository. These include:

  • COBOL, PL/I, and Assembler application programs
  • BMS map definitions for CICS screen layouts
  • Db2 source definitions for table schemas and plans
  • Java application source for web-tier or API integration components
  • z/OS Connect API definitions for REST API exposure

3.2 Build Outputs

After DBB completes compilation and dependency resolution, the following artifacts are produced:

Artifact Description
Load Modules Compiled COBOL, PL/I, Assembler, and BMS executables
Db2 Tables and Plans Database objects and access plans
JAR Files Compiled Java archives
z/OS Connect Artifacts API configuration and service bindings
Wazi Deploy Archive Packaging envelope containing all generated artifacts

4. Full and Incremental Builds

4.1 Full Build

A full build compiles all application components, packages the complete application, and prepares it for deployment. This workflow is used:

  • During initial installation of a new Bank of Z environment
  • When changes to the runtime infrastructure or environment configuration require a complete redeployment

4.2 Incremental Build

An incremental build rebuilds and deploys only the application components affected by source code changes. This workflow is intended for:

  • Day-to-day development activities
  • Implementing enhancements or fixing defects
  • Scenarios where the existing runtime environment does not need to be reprovisioned

After the initial deployment, incremental builds and deployments are triggered using the pipeline-remote.sh script. The build process automatically identifies modified source files, rebuilds the impacted components, packages the updated artifacts, and deploys them to the existing runtime.

BASH 
# Trigger an incremental build and deploy against an existing environment
./pipeline-remote.sh

Note: An incremental build requires an existing Bank of Z environment that has already been deployed successfully. Use a full build and deployment when setting up a new environment or when infrastructure changes require a complete redeployment.

5. CICS Deployment

5.1 CICS Deployment Workflow

After the build completes, Wazi Deploy installs the generated artifacts into the CICS runtime environment that has been provisioned by zconfig. The z/OS Connect APIs are then configured to route inbound requests to the CICS transaction-processing environment.

sequenceDiagram participant WD as Wazi Deploy participant ZC as zconfig participant CICS as CICS Runtime participant ZOS as z/OS Connect CLI participant GW as z/OS Connect API Gateway WD->>ZC: Provision CICS Runtime Environment ZC-->>CICS: CICS Region Initialized WD->>CICS: Install Load Modules & BMS Maps WD->>CICS: Install Db2 Plans CICS-->>WD: Artifacts Installed ZOS->>GW: Configure & Start CICS-Backed APIs GW-->>ZOS: APIs Active GW->>CICS: Route Inbound API Requests

5.2 CICS Deployment Components

The CICS deployment installs the following artifact types into the provisioned CICS region:

  • Load modules (COBOL, PL/I, Assembler, BMS)
  • Db2 table definitions and access plans
  • z/OS Connect API bindings pointing to CICS transactions

6. IMS Deployment

6.1 IMS Deployment Workflow

IMS application artifacts are deployed to the IMS region provisioned by zconfig. The z/OS Connect APIs are configured to route requests to the IMS Transaction Manager ™ environment.

sequenceDiagram participant WD as Wazi Deploy participant ZC as zconfig participant IMS as IMS TM/DB Region participant ZOS as z/OS Connect CLI participant GW as z/OS Connect API Gateway WD->>ZC: Provision IMS Runtime Environment ZC-->>IMS: IMS Region Initialized WD->>IMS: Install IMS Application Artifacts WD->>IMS: Install Db2 Plans IMS-->>WD: Artifacts Installed ZOS->>GW: Configure & Start IMS-Backed APIs GW-->>ZOS: APIs Active GW->>IMS: Route Inbound API Requests via IMS TM

6.2 IMS Deployment Components

The IMS deployment installs the following artifact types into the provisioned IMS region:

  • Load modules for IMS-managed transactions
  • Db2 table definitions and access plans
  • z/OS Connect API bindings pointing to IMS transactions via the IMS Transaction Manager

7. Tooling Summary

The following table summarizes the role of each tool in the Bank of Z build and deployment pipeline:

Tool Role
IBM DBB (Dependency Based Build) Compiles and packages all application source, performing dependency analysis to determine what needs to be rebuilt
Wazi Deploy Deploys the Wazi Deploy build archive to CICS and IMS runtime environments
zconfig Provisions the CICS and IMS runtime environments prior to artifact installation
z/OS Connect CLI Configures and starts z/OS Connect APIs, routing requests to the appropriate CICS or IMS backend

For a detailed description of what each deployment stage does at runtime, see Deploying Bank of Z.
