Repository Structure

The Bank of Z repository contains the application source, setup automation, build assets, deployment configuration, and supporting documentation required to build and deploy the application. This page describes the top-level layout, the organization of each major directory, and the conventions used across the codebase.

1. Overview

The repository is organized around a clear separation of concerns: application source code lives in src/, all provisioning and build automation lives in .setup/, IDE tooling configuration lives in .vscode/ and scripts/, and documentation lives in docs/. This structure allows developers, operators, and automation pipelines to locate and modify any part of the system without ambiguity.

The table below summarizes every top-level entry in the repository:

Directory / File Description
src/ Application source code — COBOL, BMS, IMS, z/OS Connect APIs, and the web frontend
.setup/ All automation for provisioning, building, and deploying Bank of Z
.vscode/ VS Code task definitions for triggering setup and pipeline scripts
scripts/ Utility scripts for downloading and installing IDE extensions
docs/ Product documentation
zcodescan/ ZCodeScan configuration for static analysis
dbb-app.yaml DBB application descriptor
zapp.yaml z/OS application manifest

3. Application Source (src/)

The src/ directory is the root of all deployable code. It is subdivided by runtime target — CICS, IMS, batch, API, and frontend — so that each component can be built and deployed independently.

Directory Description
src/base/cics/ COBOL programs, BMS maps, and copybooks for the CICS transaction path
src/base/ims/ COBOL programs and copybooks for the IMS transaction path
src/base/batch/ Batch application components
src/api/ z/OS Connect API project — Gradle-based build producing the API deployment artifact
src/frontend/ Browser-based frontend — HTML, CSS, JavaScript, and a Node.js dev server

4. Setup Automation (.setup/)

The .setup/ directory contains everything needed to take an empty z/OS system from zero to a fully running Bank of Z instance. It is divided into orchestration scripts (which chain stages together) and configuration and asset directories (which supply the data those scripts operate on).

4.1 Orchestration Scripts

The five orchestration scripts cover two distinct workflows: the Zowe CLI workflow (initiated from a local machine) and the GRUB workflow (initiated directly on z/OS USS). The sequence diagram below shows how a full setup run flows through these scripts.

sequenceDiagram participant Dev as Developer (Local) participant Local as setup-local.sh participant Zowe as Zowe CLI participant Remote as setup-remote.sh (USS) participant Common as setup-common.sh (USS) Dev->>Local: Execute setup-local.sh Local->>Local: Create USS workspace Local->>Local: Clone repository on USS Local->>Zowe: Invoke setup-remote.sh via Zowe CLI Zowe->>Remote: Run on z/OS USS Remote->>Common: validate-prereqs stage Common-->>Remote: ✓ Prerequisites validated Remote->>Common: environment stage Common-->>Remote: ✓ Environment configured Remote->>Common: install-bank-of-z stage Common-->>Remote: ✓ Bank of Z installed Remote-->>Zowe: Setup complete Zowe-->>Dev: Done
Script Runs on Description
setup-local.sh Local machine Creates the USS workspace, clones the repository on USS, and invokes setup-remote.sh via Zowe CLI. Used by the Zowe CLI workflow.
setup-remote.sh z/OS USS Chains the three setup stages in sequence. Used by both the Zowe CLI and GRUB workflows.
setup-common.sh z/OS USS Implements the three setup stages: validate-prereqs, environment, and install-bank-of-z.
pipeline-local.sh Local machine Uploads pipeline assets and invokes pipeline-remote.sh via Zowe CLI. Used by the Zowe CLI workflow for incremental builds.
pipeline-remote.sh z/OS USS Runs the DBB build and Wazi Deploy on USS. Used by both workflows for incremental builds.

The incremental build pipeline follows a similar pattern. Once the initial setup is complete, developers can trigger pipeline-local.sh to push source changes, run a DBB build, and deploy updates — all from their local workstation.

sequenceDiagram participant Dev as Developer (Local) participant PLocal as pipeline-local.sh participant Zowe as Zowe CLI participant PRemote as pipeline-remote.sh (USS) participant DBB as DBB Build participant WD as Wazi Deploy Dev->>PLocal: Execute pipeline-local.sh PLocal->>PLocal: Upload pipeline assets PLocal->>Zowe: Invoke pipeline-remote.sh via Zowe CLI Zowe->>PRemote: Run on z/OS USS PRemote->>DBB: Run DBB build DBB-->>PRemote: Build artifacts produced PRemote->>WD: Run Wazi Deploy WD-->>PRemote: Deployment complete PRemote-->>Dev: Pipeline finished

4.2 Configuration and Assets

Directory Description
.setup/config/ config.yaml — environment configuration consumed by all setup scripts
.setup/build/ DBB build configuration: datasets.yaml, dbb-build.yaml, language scripts, and zosattributes
.setup/deploy/ Wazi Deploy configuration and deployment method definitions
.setup/jcl/ JCL assets including Db2-grant.jcl
.setup/zconfig/ zconfig definitions for provisioning CICS and IMS regions
.setup/tasks/ Individual task scripts for DBB build, Wazi Deploy, and ZCodeScan
.setup/setup/ Individual setup stage scripts (Db2, CICS, IMS, z/OS Connect, frontend)
.setup/lib/ Shared shell library functions used by the orchestration scripts

The central configuration file for the entire setup process is .setup/config/config.yaml. All orchestration and stage scripts read from this file to determine target datasets, region names, hostnames, and other environment-specific values.

5. IDE Extension Scripts (scripts/)

The scripts/ directory provides three Node.js utilities for managing the IDE extensions that developers need to work with Bank of Z source code. These scripts support both IBM Bob Premium Package for Z and Visual Studio Code.

Script Description
download-vsix.js Downloads all required IDE extension VSIX packages
install-bobide-vsix.js Installs downloaded VSIX packages into IBM Bob Premium Package for Z
install-vscode-vsix.js Installs downloaded VSIX packages into VS Code

A typical extension setup workflow runs the scripts in the following order:

graph LR A["download-vsix.js\nDownload VSIX packages"] --> B{"Target IDE"} B -->|"IBM Bob Premium"| C["install-bobide-vsix.js\nInstall into Bob IDE"] B -->|"VS Code"| D["install-vscode-vsix.js\nInstall into VS Code"]

Usage instructions for these scripts are documented in scripts/README.md.

6. VS Code Tasks (.vscode/)

The .vscode/ directory contains task definitions that surface the setup and pipeline scripts as named tasks within VS Code. This allows developers to trigger provisioning, builds, and deployments directly from the IDE without manually invoking shell scripts from a terminal.

These tasks act as a thin wrapper over the scripts in .setup/ and scripts/, passing any required arguments and presenting output in the VS Code terminal panel.

7. Static Analysis (zcodescan/)

The zcodescan/ directory holds the configuration for ZCodeScan, the static analysis tool used to inspect COBOL and other mainframe source files in the repository. ZCodeScan is invoked as part of the pipeline via the task scripts in .setup/tasks/.

8. Application Manifests

Two manifest files sit at the root of the repository and describe the application to the IBM Z build and deployment toolchain:

File Description
dbb-app.yaml DBB application descriptor — defines source groups, build properties, and language configurations consumed by the DBB build framework
zapp.yaml z/OS application manifest — used by z/OS-aware tooling to identify the application and its components

These files are the authoritative source of application identity and build configuration metadata. Changes to dataset naming conventions, language assignments, or build order are reflected here.

9. Documentation (docs/)

The docs/ directory maintains product documentation alongside the application source, ensuring that documentation stays in sync with code changes. The documentation site covers:

  • Architecture — solution design and component relationships
  • Installation and Setup — step-by-step deployment instructions
  • Reference — configuration options, repository structure, commands, and glossary

For solution design information, see the Architecture section. For deployment instructions, see Installation and Setup.
