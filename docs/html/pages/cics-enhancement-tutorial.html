Tutorial: CICS Enhancement Scenario

1. Overview

This tutorial walks you through an end-to-end scenario of enhancing a CICS-based transaction in the Bank of Z application. Specifically, you will add a new customer email field to the existing CICS implementation — a representative example of a real-world IBM Z application enhancement.

The tutorial is divided into two parts:

  • Part 1 focuses on understanding the existing application architecture and planning the enhancement using IBM Z tools.
  • Part 2 covers implementing the planned changes, deploying the updated application, and validating the results.

By the end of this tutorial, you will have hands-on experience with a complete IBM Z development lifecycle — from codebase exploration and impact analysis through to deployment and verification.

1.1 What You Will Learn

By completing this tutorial, you will learn how to:

  • Understand the CICS application architecture and request flow
  • Analyze the impact of an application enhancement
  • Plan application changes using Bob AI and Z Understand
  • Modify application artifacts, including database definitions and COBOL programs
  • Use IBM Z Open Editor features to navigate and review application code
  • Build and deploy updated CICS application components
  • Verify the enhancement using the Bank of Z web application

1.2 Prerequisites

Before starting this tutorial, ensure that you have:

  • Completed the Quick Start
  • Successfully built and deployed Bank of Z
  • A working Bank of Z development environment

2. System Architecture

The Bank of Z CICS application follows a layered architecture, where a web front-end communicates with CICS transactions running on IBM Z. These transactions interact with underlying data stores and are built, packaged, and deployed through a structured pipeline.

The diagram below illustrates the high-level system architecture and the key components involved in this tutorial:

graph TD A[Bank of Z Web Application] -->|HTTP Request| B[CICS Transaction Gateway] B -->|CICS Commands| C[CICS Region on IBM Z] C -->|Read/Write| D[(Customer Database)] C --> E[COBOL Application Programs] E -->|Data Access| D F[Developer Workstation] -->|Code Changes| G[IBM Z Open Editor / VS Code] G -->|Source Updates| H[Source Code Repository] H -->|Trigger| I[Bank of Z Build Pipeline] I -->|Deploy Artifacts| C J[Bob AI] -.->|Implementation Guidance| G K[Z Understand] -.->|Impact Analysis & Navigation| G

The core components involved in this enhancement scenario are:

Component Role
Bank of Z Web Application Front-end interface used to verify the enhancement
CICS Region Hosts the transactions and COBOL programs on IBM Z
COBOL Application Programs Business logic implementing customer data operations
Customer Database Stores customer records, including the new email field
IBM Z Open Editor IDE used to navigate and modify COBOL source code
Bob AI AI assistant that helps plan and implement changes
Z Understand Tool used for codebase exploration and impact analysis
Bank of Z Build Pipeline Automates building and deploying updated components

3. Part 1 — Understand and Plan the Enhancement

Before writing a single line of code, it is essential to understand the existing application structure, identify all components that will be affected, and produce a clear implementation plan. This part of the tutorial uses Z Understand and Bob AI to perform that analysis.

  • Understanding the CICS application architecture — identifying transactions, programs, maps, and data definitions
  • Performing impact analysis — determining which programs, copybooks, and database schemas need to be updated to accommodate the new email field
  • Tracing the application data flow — following how a customer record moves through the system from the web request to the database
  • Generating an implementation plan — using Bob AI to produce a structured, step-by-step guide for the enhancement
  • Creating an implementation checklist — a concrete list of artifacts and changes to be made

4. Part 2 — Implement and Validate the Enhancement

With a clear implementation plan in hand from Part 1, this section covers the actual development work: updating source artifacts, modifying COBOL programs, running the build and deployment pipeline, and verifying the results.

4.1 Implementation and Deployment Workflow

The diagram below illustrates the end-to-end flow from source code changes through to validation:

graph TD A[Implementation Plan from Part 1] --> B[Update DB Schema / Copybooks] B --> C[Modify COBOL Programs] C --> D[Review Changes in IBM Z Open Editor] D --> E{Changes Correct?} E -- No --> C E -- Yes --> F[Commit to Source Repository] F --> G[Trigger Bank of Z Build Pipeline] G --> H[Build COBOL Programs and DB Definitions] H --> I[Deploy to CICS Region on IBM Z] I --> J[Validate Database Updates] J --> K[Verify via Bank of Z Web Application] K --> L{Enhancement Verified?} L -- No --> C L -- Yes --> M[Enhancement Complete ✓]

This iterative loop ensures that any issues found during validation can be addressed before the enhancement is considered complete.

4.2 Updating Application Artifacts

The enhancement requires changes across several layers of the application. The typical artifacts updated when adding a new field to a CICS application include:

  • Database definitions — adding the EMAIL column to the customer table
  • COBOL copybooks — extending the customer data structure to include the new field
  • CICS maps — updating BMS map definitions if the field appears on a screen
  • COBOL application programs — adding logic to read, write, and process the new email field

A typical COBOL copybook change to add an email field would look like:

COBOL 
01 CUSTOMER-RECORD.
   05 CUST-ID            PIC 9(8).
   05 CUST-FIRST-NAME    PIC X(20).
   05 CUST-LAST-NAME     PIC X(30).
   05 CUST-ADDRESS       PIC X(50).
   05 CUST-PHONE         PIC X(15).
   05 CUST-EMAIL         PIC X(50).   *> NEW FIELD ADDED

And a corresponding program update to handle the new field:

COBOL 
* Move email from input to customer record
MOVE WS-INPUT-EMAIL TO CUST-EMAIL

* Write updated customer record
EXEC CICS WRITE
    FILE('CUSTFILE')
    FROM(CUSTOMER-RECORD)
    RIDFLD(CUST-ID)
END-EXEC

4.3 Using IBM Z Open Editor

IBM Z Open Editor provides rich IDE features for working with COBOL and CICS applications directly in VS Code. During implementation, the editor assists with:

  • Code navigation — jumping between programs, copybooks, and data definitions
  • Syntax highlighting and error detection — catching COBOL syntax issues before compilation
  • Hover documentation — viewing data structure definitions inline
  • Integration with Z Understand — linking editor navigation to the broader application map

4.4 Using Bob AI for Implementation Assistance

Bob AI acts as an intelligent coding assistant throughout the implementation. It can:

  • Suggest the correct COBOL syntax for adding new data fields
  • Identify which programs need to be updated based on the impact analysis
  • Generate boilerplate code for common CICS patterns
  • Review proposed changes and flag potential issues

4.5 Activities Covered in Part 2

The Part 2 demonstration covers the following activities:

  • Updating application artifacts — modifying copybooks, database definitions, and program source files
  • Reviewing and implementing code changes — using the implementation checklist from Part 1 to guide development
  • Using IBM Z Open Editor to navigate the codebase and apply COBOL modifications
  • Using Bob AI to assist with code generation and review
  • Running the Bank of Z build and deployment pipeline — compiling and linking updated programs and deploying to the CICS region
  • Validating database updates — confirming the new email field exists and is populated correctly in the customer database
  • Verifying the enhancement through the Bank of Z web application — confirming the email field appears and behaves correctly in the user interface
