Application Components

Bank of Z consists of several application and infrastructure components that work together to provide a unified banking experience. These components enable the application to deliver modern web-based banking services while leveraging IBM Z transaction-processing technologies. Requests are submitted through a browser-based user interface and routed through z/OS Connect to the appropriate transaction-processing environment, where business logic executes and data is persisted across multiple database systems.

1. Overview

Bank of Z is a hybrid banking application that combines modern web technologies with IBM Z enterprise transaction-processing systems. The application integrates a browser-based UI, API middleware, CICS, IMS Transaction Manager (IMS TM), Db2 for z/OS, IMS databases, z/OS Connect, and IBM MQ into a single cohesive banking solution.

Although the underlying transaction-processing path may differ depending on the request, users interact with a single banking application through a consistent web interface. This architecture demonstrates how multiple IBM Z transaction-processing technologies can be integrated into a unified application while supporting modern APIs, shared data services, and DevSecOps workflows.

The application combines the following high-level capabilities:

  • A browser-based user interface for customer, account, and transaction management
  • z/OS Connect APIs bridging the UI and backend systems
  • CICS and IMS TM transaction processing
  • Db2 and IMS databases for persistent data storage
  • IBM MQ for asynchronous messaging and external system integration

2. System Architecture

The Bank of Z architecture follows a layered model. The user interface communicates with z/OS Connect through REST APIs. z/OS Connect routes requests to either the CICS or IMS TM transaction-processing environment. Both environments share access to Db2 databases, while IMS TM also reads from and writes to IMS databases. IBM MQ enables asynchronous communication with external systems, such as Bank of Q.

The following diagram illustrates the high-level system architecture and how each component relates to the others:

graph TD UI[Bank of Z UI\nBrowser-Based Interface] ZC[z/OS Connect\nAPI Layer] CICS[CICS\nTransaction Processing] IMS[IMS TM\nTransaction Processing] DB2_MA[Money & Account\nManagement Db2 Database] DB2_AH[Account History\nDb2 Database] IMS_DB[Money & Account\nManagement IMS Database] MQ[IBM MQ\nMessaging] BOQ[Bank of Q\nExternal Banking System] UI -->|REST API| ZC ZC -->|CICS Path| CICS ZC -->|IMS Path| IMS CICS --> DB2_MA CICS --> DB2_AH IMS --> DB2_MA IMS --> IMS_DB MQ --> BOQ CICS --> MQ IMS --> MQ

The architecture is intentionally layered so that each tier has a well-defined responsibility:

Layer Component(s) Responsibility
Presentation Bank of Z UI User interaction via browser
API Gateway z/OS Connect REST API routing to backend systems
Transaction Processing CICS, IMS TM Business logic execution
Data Db2, IMS Databases Persistent storage of accounts and transactions
Messaging IBM MQ Asynchronous, reliable inter-system communication
External Systems Bank of Q Demonstration of inter-application money transfers

3. Component Descriptions

3.1 Bank of Z UI

The Bank of Z user interface provides a browser-based experience for performing banking operations. It enables users to manage customer information, accounts, and transactions through a single application interface without needing to know which backend system processes the request.

Key characteristics:

  • Browser-based, requiring no client-side installation
  • Presents a unified view regardless of whether CICS or IMS TM is processing the request
  • Communicates with the backend exclusively through REST APIs exposed by z/OS Connect

3.2 z/OS Connect

z/OS Connect provides the API layer between the user interface and the backend transaction-processing systems. It exposes services that enable the Bank of Z UI to communicate with CICS and IMS applications through REST APIs.

Key characteristics:

  • Acts as the single integration point between the modern web tier and IBM Z backend systems
  • Routes requests to either the CICS or IMS TM processing path
  • Abstracts the complexity of backend systems from the user interface

The following sequence diagram illustrates a typical request flow through z/OS Connect:

sequenceDiagram participant User as User (Browser) participant UI as Bank of Z UI participant ZC as z/OS Connect participant CICS as CICS participant IMS as IMS TM participant DB2 as Db2 Database User->>UI: Initiate banking operation UI->>ZC: REST API Request alt CICS Processing Path ZC->>CICS: Route to CICS CICS->>DB2: Read / Write data DB2-->>CICS: Return data CICS-->>ZC: Response else IMS Processing Path ZC->>IMS: Route to IMS TM IMS->>DB2: Read / Write data DB2-->>IMS: Return data IMS-->>ZC: Response end ZC-->>UI: API Response UI-->>User: Display result

3.3 CICS

CICS provides transaction-processing services for the Bank of Z application along the CICS processing path. It handles banking requests including customer management, account management, and transaction processing.

Key characteristics:

  • Processes requests routed to it by z/OS Connect
  • Executes business logic for the CICS path
  • Reads from and writes to the Money and Account Management Db2 database
  • Reads from and writes to the Account History Db2 database
  • Can publish messages to IBM MQ for asynchronous communication

3.4 IMS Transaction Manager (IMS TM)

IMS Transaction Manager (IMS TM) provides transaction-processing services for the Bank of Z application along the IMS processing path. It processes banking requests including customer management, account management, and transaction processing.

Key characteristics:

  • Processes requests routed to it by z/OS Connect
  • Executes business logic for the IMS path
  • Reads from and writes to the Money and Account Management IMS database
  • Also accesses the Money and Account Management Db2 database for shared data
  • Can publish messages to IBM MQ for asynchronous communication

3.5 Money and Account Management Db2 Database

The Money and Account Management Db2 database stores account and transaction data used by the application. It serves as the primary data store for the CICS processing path and is also accessed by IMS-based transactions, making it a shared data service across both processing paths.

Key characteristics:

  • Primary data store for the CICS processing path
  • Shared and accessible by IMS TM transactions
  • Stores current account and customer data

3.6 Account History Db2 Database

The Account History Db2 database stores historical account and transaction information used for inquiry and reporting functions.

Key characteristics:

  • Stores historical transaction and account records
  • Supports inquiry and reporting operations
  • Accessed primarily through the CICS processing path

3.7 Money and Account Management IMS Database

The Money and Account Management IMS database supports account management functions specifically for the IMS processing path. It enables IMS applications to manage and retrieve customer and account information.

Key characteristics:

  • Dedicated to the IMS processing path
  • Enables IMS applications to manage customer and account information
  • Works alongside the shared Db2 database

3.8 IBM MQ

IBM MQ provides messaging capabilities that enable asynchronous communication between Bank of Z and external systems. It supports integration scenarios that require reliable message delivery and decoupled processing.

Key characteristics:

  • Enables asynchronous, reliable message delivery
  • Decouples Bank of Z from external systems
  • Supports inter-application communication and money transfer scenarios

The following diagram shows the asynchronous messaging flow between Bank of Z and Bank of Q:

sequenceDiagram participant CICS as CICS / IMS TM participant MQ as IBM MQ participant BOQ as Bank of Q CICS->>MQ: Place message on queue MQ-->>BOQ: Deliver message asynchronously BOQ->>MQ: Place response on reply queue MQ-->>CICS: Deliver response

3.9 Bank of Q

Bank of Q represents an external banking system that exchanges information with Bank of Z through IBM MQ. It is used to demonstrate inter-application communication and money transfer scenarios.

Key characteristics:

  • Acts as an external banking system peer to Bank of Z
  • Communicates with Bank of Z exclusively through IBM MQ
  • Demonstrates decoupled, asynchronous inter-system messaging

4. Component Relationships

The diagram below provides a focused view of how the transaction-processing components relate to the shared data layer:

graph LR CICS[CICS] IMS[IMS TM] DB2_MA[(Money & Account\nManagement Db2)] DB2_AH[(Account History Db2)] IMS_DB[(Money & Account\nManagement IMS DB)] CICS -->|Read / Write| DB2_MA CICS -->|Read / Write| DB2_AH IMS -->|Read / Write| DB2_MA IMS -->|Read / Write| IMS_DB

The Bank of Z UI communicates with z/OS Connect through REST APIs. z/OS Connect provides access to the underlying transaction-processing environments, where business logic executes and data is stored in Db2 for z/OS and IMS databases. IBM MQ supports asynchronous communication with external systems such as Bank of Q.

Together, these components provide a hybrid IBM Z application that combines:

  • Modern user interfaces — a browser-based UI delivering a consistent user experience
  • API-driven integration — z/OS Connect exposing REST APIs to bridge modern and legacy systems
  • Enterprise transaction processing — CICS and IMS TM providing reliable, high-throughput processing
  • Shared data services — Db2 and IMS databases storing and managing persistent data
  • Asynchronous messaging — IBM MQ enabling reliable, decoupled communication with external systems
