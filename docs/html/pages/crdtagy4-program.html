CRDTAGY4 - Simulated Credit Agency Program

CRDTAGY4 is a COBOL program operating within the IBM CICS Transaction Server environment, designed to simulate an external credit bureau as part of the CICS Asynchronous API framework. When invoked, the program receives a customer data record through a named CICS channel and container, introduces a randomised processing delay of between 1 and 3 seconds to emulate the unpredictable response times typical of real-world external credit agencies, generates a random credit score between 1 and 999, and writes the enriched customer record back to the originating container for the parent program to retrieve. Because the parent program enforces a fixed 3-second timeout window, the deliberate randomised delay means there is approximately a one-in-three chance that a response will not be returned within the allowed time — intentionally simulating the real-world scenario where a credit agency does not always respond promptly.

1. Overview

CRDTAGY4 acts as a stand-in for an external credit bureau. When a banking application needs to assess a customer’s creditworthiness, it passes customer details to this program through an internal CICS data channel (CIPCREDCHANN) via a container (CIPD). The program then:

  • Waits a random amount of time (1–3 seconds) to simulate network and processing latency.
  • Reads the customer record from the CICS container.
  • Generates a random credit score between 1 and 999.
  • Writes the updated customer record (with the new credit score) back to the container.
  • Returns control to the CICS task dispatcher.

If anything goes wrong at any step — the delay fails, the container read fails, or the container write fails — the program logs full diagnostic information and calls a dedicated error handler (ABNDPROC) before shutting down gracefully.

5. Business Rules

5.1 Generate Random Credit Agency Response Delay

Paragraph: PREMIERE_A010

Purpose: Calculates a random delay amount between 1 and 3 seconds using the CICS task number as a seed, simulating variable response time from an external credit agency. This introduces realistic, non-deterministic latency into the credit scoring process.

Core Decision Logic:

  • Delay duration is randomly generated within the range of 1 to 3 seconds to simulate variable credit agency response time.
  • EIBTASKN is used as the random seed to ensure a unique delay per task execution.
  • Because the parent program enforces a 3-second timeout, this range means approximately a 1-in-3 chance of not responding in time.
COBOL 
COMPUTE WS-DELAY-AMT = ((3 - 1)
                 * FUNCTION RANDOM(WS-SEED)) + 1.

5.2 Generate Random Credit Score

Purpose: After the delay completes and the customer record is retrieved, a random credit score is generated in the range 1–999.

  • No seed argument is passed to FUNCTION RANDOM on this second call — the random sequence continues from where it was seeded in the delay computation step.
  • Re-seeding at this point is intentionally avoided to ensure statistical variety between the delay and the score values.
COBOL 
COMPUTE WS-NEW-CREDSCORE = ((999 - 1)
                 * FUNCTION RANDOM) + 1.
MOVE WS-NEW-CREDSCORE TO CUSTOMER-CREDIT-SCORE OF WS-CONT-IN.

6.1 Execution Steps Described

Step 1 — Initialisation (A010)

The program begins by setting up the key channel and container identifiers and loading the random seed from the CICS task number:

COBOL 
MOVE 'CIPD'         TO WS-CONTAINER-NAME.
MOVE 'CIPCREDCHANN' TO WS-CHANNEL-NAME.
MOVE EIBTASKN       TO WS-SEED.

Step 2 — Compute and Apply Random Delay

A random delay between 1 and 3 seconds is computed using EIBTASKN as the seed, then the task is suspended for that duration:

COBOL 
COMPUTE WS-DELAY-AMT = ((3 - 1)
                 * FUNCTION RANDOM(WS-SEED)) + 1.

EXEC CICS DELAY
    FOR SECONDS(WS-DELAY-AMT)
    RESP(WS-CICS-RESP)
    RESP2(WS-CICS-RESP2)
END-EXEC.

Step 3 — Delay Error Handling

If the CICS DELAY command returns a non-normal response, the program populates ABNDINFO-REC, calls the POPULATE-TIME-DATE subroutine, links to ABNDPROC, and issues a hard abend with code PLOP.

Step 4 — GET Container

The byte length of WS-CONT-IN is computed, and the customer record is retrieved from the channel/container:

COBOL 
COMPUTE WS-CONTAINER-LEN = LENGTH OF WS-CONT-IN.

EXEC CICS GET CONTAINER(WS-CONTAINER-NAME)
    CHANNEL(WS-CHANNEL-NAME)
    INTO(WS-CONT-IN)
    FLENGTH(WS-CONTAINER-LEN)
    RESP(WS-CICS-RESP)
    RESP2(WS-CICS-RESP2)
END-EXEC.

Step 5 — Generate Random Credit Score

No seed is passed to FUNCTION RANDOM on this call — the sequence continues from the earlier seed, ensuring variety:

COBOL 
COMPUTE WS-NEW-CREDSCORE = ((999 - 1)
                 * FUNCTION RANDOM) + 1.
MOVE WS-NEW-CREDSCORE TO CUSTOMER-CREDIT-SCORE OF WS-CONT-IN.

Step 6 — PUT Container

The updated record (with new credit score) is written back to the container:

COBOL 
COMPUTE WS-CONTAINER-LEN = LENGTH OF WS-CONT-IN.

EXEC CICS PUT CONTAINER(WS-CONTAINER-NAME)
    FROM(WS-CONT-IN)
    FLENGTH(WS-CONTAINER-LEN)
    CHANNEL(WS-CHANNEL-NAME)
    RESP(WS-CICS-RESP)
    RESP2(WS-CICS-RESP2)
END-EXEC.

Step 7 — Normal Exit

On success, GET-ME-OUT-OF-HERE issues EXEC CICS RETURN, returning control to the CICS task dispatcher.

7. Paragraphs

7.1 A010 — Main Processing Paragraph

Purpose: The primary entry paragraph of the program. Orchestrates the full credit-scoring simulation — generating a random delay, retrieving the customer record, computing a new credit score, and writing the result back.

Key actions:

  • Initialises WS-CONTAINER-NAME to 'CIPD' and WS-CHANNEL-NAME to 'CIPCREDCHANN'
  • Seeds WS-SEED from EIBTASKN
  • Computes and applies a random CICS delay (1–3 seconds)
  • Handles delay failure by populating ABNDINFO-REC, linking to ABNDPROC, and issuing CICS ABEND ABCODE('PLOP')
  • Retrieves the customer record via CICS GET CONTAINER
  • Generates a random credit score (1–999) and places it into CUSTOMER-CREDIT-SCORE
  • Writes the updated record back via CICS PUT CONTAINER
  • Calls GET-ME-OUT-OF-HERE on both success and error paths

7.2 A999 — End of PREMIERE Section

Purpose: Formal section terminator for the PREMIERE SECTION. Contains only an EXIT statement, never explicitly branched to. Marks the structural boundary of the section.

7.3 GET-ME-OUT-OF-HERE — CICS Return Paragraph

Purpose: Provides a single, centralised exit point from the program by issuing EXEC CICS RETURN. Called on both error conditions and successful completion.

COBOL 
GET-ME-OUT-OF-HERE SECTION.
    EXEC CICS RETURN END-EXEC.

7.4 GMOFH999 — End of GET-ME-OUT-OF-HERE Section

Purpose: Formal section terminator for the GET-ME-OUT-OF-HERE SECTION. Contains only an EXIT statement.

7.5 POPULATE-TIME-DATE — Date and Time Population Paragraph

Purpose: Retrieves and formats the current CICS system time into working-storage fields used to populate abend diagnostic records. Called exclusively from the A010 error-handling block when a CICS DELAY failure occurs.

COBOL 
POPULATE-TIME-DATE SECTION.
    EXEC CICS ASKTIME
        ABSTIME(WS-U-TIME)
    END-EXEC.

    EXEC CICS FORMATTIME
        ABSTIME(WS-U-TIME)
        DDMMYYYY(WS-ORIG-DATE)
        TIME(WS-TIME-NOW)
        DATESEP
    END-EXEC.
  • CICS ASKTIME — Retrieves the CICS absolute time into WS-U-TIME
  • CICS FORMATTIME — Formats the time into DD/MM/YYYY (stored in WS-ORIG-DATE) and HHMMSS (stored in WS-TIME-NOW, which is overlaid by WS-TIME-NOW-GRP providing HH, MM, and SS sub-fields)

7.6 PTD999 — End of POPULATE-TIME-DATE Section

Purpose: Formal section terminator for the POPULATE-TIME-DATE SECTION. Contains only an EXIT statement.

8. Error Handling

The following sequence diagram illustrates the error handling path triggered by a CICS DELAY failure:

sequenceDiagram participant CRDTAGY4 participant CICS participant ABNDPROC CRDTAGY4->>CICS: EXEC CICS DELAY FOR SECONDS(WS-DELAY-AMT) CICS-->>CRDTAGY4: RESP=Non-Normal (e.g. 22), RESP2=1 CRDTAGY4->>CRDTAGY4: Initialize ABNDINFO-REC CRDTAGY4->>CICS: EXEC CICS ASSIGN APPLID / PROGRAM CICS-->>CRDTAGY4: APPLID, PROGRAM NAME CRDTAGY4->>CICS: EXEC CICS ASKTIME / FORMATTIME CICS-->>CRDTAGY4: Formatted Date and Time CRDTAGY4->>CRDTAGY4: Populate ABND-FREEFORM, ABND-CODE='PLOP' CRDTAGY4->>CICS: DISPLAY '*** The delay messed up ! ***' CRDTAGY4->>ABNDPROC: EXEC CICS LINK COMMAREA(ABNDINFO-REC) ABNDPROC-->>CRDTAGY4: Return from LINK CRDTAGY4->>CICS: EXEC CICS ABEND ABCODE('PLOP') Note over CRDTAGY4,CICS: Task terminated - no further processing

8.1 CICS DELAY Failure — Abend Path

  • Response codes EIBRESP and EIBRESP2 are evaluated after EXEC CICS DELAY.
  • If non-normal: ABNDINFO-REC is fully populated (see Section 4.2), POPULATE-TIME-DATE is called to capture current date/time, EXEC CICS LINK PROGRAM('ABNDPROC') passes the diagnostic record, then EXEC CICS ABEND ABCODE('PLOP') forces task termination.
  • All further processing (GET, score generation, PUT) is blocked.

8.2 CICS GET CONTAINER Failure — Controlled Exit

  • WS-CICS-RESP is evaluated against DFHRESP(NORMAL) after the GET command.
  • On failure: two DISPLAY statements emit container name, channel name, length, and both response codes to the CICS log.
  • GET-ME-OUT-OF-HERE is performed, issuing EXEC CICS RETURN for an orderly exit (no hard abend).

8.3 CICS PUT CONTAINER Failure — Controlled Exit

  • WS-CICS-RESP is evaluated against DFHRESP(NORMAL) after the PUT command.
  • On failure: two DISPLAY statements mirror the GET error reporting pattern.
  • GET-ME-OUT-OF-HERE is performed, issuing EXEC CICS RETURN.
  • The updated credit score is lost in this scenario — no retry or correction occurs.

8.4 Normal Termination

  • At the end of the successful processing flow, GET-ME-OUT-OF-HERE is called unconditionally.
  • This ensures the program always terminates via an explicit EXEC CICS RETURN, preventing accidental fall-through after any error branch.

10. Constraints

10.1 Data Constraints

Field Constraint
CUSTOMER-EYECATCHER Must equal 'CUST' (level-88 condition CUSTOMER-EYECATCHER-VALUE)
CUSTOMER-SORTCODE PIC 9(6) — exactly 6 numeric digits; hardcoded constant SORTCODE = 987654
CUSTOMER-NUMBER PIC 9(10) — exactly 10 numeric digits
CUSTOMER-STATUS PIC X(10) — only 'ACTIVE', 'INACTIVE', or 'SUSPENDED' have defined semantics
CUSTOMER-CREDIT-SCORE PIC 999 — generated range enforced as 1–999 via ((999 - 1) * FUNCTION RANDOM) + 1
CUSTOMER-TITLE PIC X(10) — maximum 10 characters
CUSTOMER-FIRST-NAME / CUSTOMER-LAST-NAME PIC X(50) — maximum 50 characters each
CUSTOMER-ADDRESS lines / city / country PIC X(50) — maximum 50 characters each
CUSTOMER-POSTCODE PIC X(10) — maximum 10 characters
CUSTOMER-PHONE PIC X(20) — maximum 20 characters

10.2 Channel and Container Constraints

  • Fixed container name — 'CIPD' (space-padded to 16 characters, matching PIC X(16)); no other container is attempted.
  • Fixed channel name — 'CIPCREDCHANN' (space-padded to 16 characters); the program exclusively communicates over this channel.
  • Container length must equal record length — WS-CONTAINER-LEN is always computed as LENGTH OF WS-CONT-IN before both GET and PUT; no partial transfers are possible.
  • Successful GET required before credit score write — If GET CONTAINER returns non-normal, the program exits immediately; credit score computation and PUT are never reached.

10.3 Timing and Delay Constraints

  • Delay range is 1–3 seconds — ((3 - 1) * FUNCTION RANDOM(WS-SEED)) + 1; a delay of 0 is never generated.
  • Seed must be EIBTASKN — WS-SEED is populated exclusively from EIBTASKN; the sequence is unique per task but deterministic given the same task number.
  • Delay must complete normally — If CICS DELAY fails, all subsequent processing is blocked and the task abends with code PLOP.
  • Parent timeout implied at 3 seconds — The ~1-in-3 chance of timeout is by architectural design.

10.4 Sequencing Constraints

The following strict operation order must be respected; each step is gated on the success of the prior:

  1. Seed generation (EIBTASKN → WS-SEED)
  2. Random delay computation and execution (CICS DELAY)
  3. Container length calculation (LENGTH OF WS-CONT-IN)
  4. Container data retrieval (CICS GET CONTAINER)
  5. Credit score computation and population (COMPUTE WS-NEW-CREDSCORE, MOVE)
  6. Container length recalculation
  7. Container data write-back (CICS PUT CONTAINER)
  8. Program return (CICS RETURN)

Additionally, FUNCTION RANDOM is called with a seed only once (step 2). The subsequent call in step 5 uses no seed argument to continue the same sequence — reseeding at step 5 is explicitly prohibited.

10.5 Error Handling Constraints

  • ABNDINFO-REC must be fully populated before CICS LINK — partial population would produce incomplete diagnostic records.
  • ABND-SQLCODE is always zero — no SQL operations occur in this program.
  • Abend code is always 'PLOP' — no conditional abend codes are used.
  • Non-normal PUT terminates immediately — the updated credit score is lost on PUT failure; no retry occurs.

All other fields Unchanged from input

11.2 Example 2 — Timeout Scenario (Credit Score Not Returned in Time)

Context: EIBTASKN = 5678 causes WS-DELAY-AMT = 3. The parent program waits a maximum of 3 seconds.

Processing:

  1. EXEC CICS DELAY FOR SECONDS(3) is issued — the program does not respond within the parent’s timeout window.
  2. The parent moves on without this agency’s result.
  3. CRDTAGY4 eventually completes: reads container, generates score 391, writes it back.
  4. Because the parent has already timed out, the response arrives too late and is discarded.

Output: No credit score received from this agency within the deadline. This is intentional by design — it simulates the real-world unpredictability of external credit agency communications.

11.3 Example 3 — CICS DELAY Failure (Abend Path)

Input: Same customer record as Example 11.1, but CICS DELAY returns RESP=22, RESP2=1.

Processing:

  1. WS-CICS-RESP ≠ DFHRESP(NORMAL) → failure path entered.
  2. ABNDINFO-REC is initialized and fully populated:
    • ABND-RESPCODE = 22, ABND-RESP2CODE = 1
    • ABND-APPLID, ABND-TRANID, ABND-TASKNO-KEY populated from EIB
    • ABND-DATE/ABND-TIME populated via POPULATE-TIME-DATE
    • ABND-CODE = 'PLOP'
    • ABND-FREEFORM = 'A010 - *** The delay messed up! *** EIBRESP=+00000022 RESP2=+00000001'
  3. EXEC CICS LINK PROGRAM('ABNDPROC') COMMAREA(ABNDINFO-REC) executed.
  4. EXEC CICS ABEND ABCODE('PLOP') terminates the task.

Output: Task abends with code PLOP. ABNDPROC receives the full diagnostic record. No credit score is written back to the container.
