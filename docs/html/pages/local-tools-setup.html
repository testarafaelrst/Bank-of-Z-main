Local Tools Setup

This page describes how to install and configure the local tools required for Bank of Z development. Before you begin, ensure that you have cloned the Bank of Z repository to your local machine. Git is required for all workflows.

1. Overview

Setting up a local development environment for Bank of Z involves three major areas: configuring an IDE, establishing a Zowe profile for z/OS connectivity, and installing deployment tooling. Each of these components plays a distinct role:

  • The IDE provides a rich development experience for browsing, editing, and managing Bank of Z source code.
  • The Zowe profile acts as the single source of connection credentials shared between IDE extensions and CLI tooling.
  • Deployment tools (either Zowe CLI or GRUB) are responsible for pushing local changes to your z/OS system.

The setup process is modular — IDE configuration is independent of the deployment workflow you choose, but both the IDE and the deployment tooling depend on having a correctly configured Zowe profile.

This architecture shows that the Zowe profile is the central configuration artifact. All local tools — the IDE, Zowe CLI, and GRUB — read from the same ~/.zowe/zowe.config.json file. This means you configure connectivity once, and all tools benefit from that configuration.

3. IDE Setup

An IDE is required to browse, edit, and manage Bank of Z source code. IDE setup is independent of your chosen deployment workflow and should be completed before configuring deployment tooling.

3.1 Prerequisites

Java 21 is required to run the IDE and its embedded tooling. Install IBM Semeru Runtime for Java 21 or later, and then verify the installation:

BASH 
java -version

3.2 Choosing an IDE

For the best experience and to follow the tutorials in the documentation, use IBM Bob Premium Package for Z. Alternatively, you can use Visual Studio Code with the required IBM Z extensions.

Note: If you are using IBM Bob Premium Package for Z and an extension is unavailable in the Open VSX Marketplace, download the VSIX package and install it manually.

3.3 Required Extensions

Install the following extensions in your IDE:

Extension Description VS Code Marketplace Open VSX VSIX

Note: For IBM MQ, there is no IBM extension in the VS Code Marketplace. See the IBM MQ Console extension available from the ibm-messaging GitHub group.

3.4 Installing Extensions from a Marketplace

  1. Open the Extensions view in your IDE.
  2. Search for the extension by name.
  3. Select Install.

3.5 Installing VSIX Packages Manually

  1. Download the VSIX file using the link in the table above.
  2. Open the Extensions view.
  3. Select More Actions (…) → Install from VSIX…
  4. Browse to the downloaded file and complete the installation.

3.6 Automated VSIX Download and Install

Bank of Z includes scripts to download and install all required VSIX packages in one step.

Download all packages:

BASH 
node scripts/download-vsix.js [output-directory]

The default output directory is ./vsix-extensions.

Install into IBM Bob Premium Package for Z:

BASH 
# First add bobide to PATH:
# View > Command Palette > Shell Command: Install 'bobide' command in PATH

node scripts/install-bobide-vsix.js [output-directory]

Install into VS Code:

BASH 
# First add code to PATH:
# View > Command Palette > Shell Command: Install 'code' command in PATH

node scripts/install-vscode-vsix.js [output-directory]

3.7 Verifying the IDE Configuration

After completing the installation:

  1. Launch the IDE.
  2. Confirm all required extensions are installed and enabled.
  3. Open the Bank of Z repository and confirm that the workspace tasks are available from Terminal → Run Task.

4. Zowe Profile Setup

A Zowe profile stores the connection details that IDE extensions (Zowe Explorer, IBM Z Open Debug) and Zowe CLI use to communicate with your z/OS system. Configure this once — both your IDE and all deployment tooling share the same profile.

The following diagram illustrates how the profile is consumed by the various tools:

graph LR Config["~/.zowe/zowe.config.json"] Config -->|host + port 10443| ZoweExp["Zowe Explorer\n(IDE Extension)"] Config -->|host + port 8195| RSEExp["RSE API\n(IDE Extension)"] Config -->|host + port 22| SSHConn["SSH Connection"] Config -->|dpsPort 8192 / rdsPort 8194| Debugger["IBM Z Open Debug\n(IDE Extension)"] Config -->|account + logonProcedure| TSOConn["TSO Session"] Config -->|host + credentials| ZoweCLI["Zowe CLI"]

4.1 Creating the Profile

Create ~/.zowe/zowe.config.json with the following content. Update the fields marked below for your environment:

  • host — Host name or IP address of your z/OS system.
  • account — Your TSO account number.
  • logonProcedure — Your TSO logon procedure.
  • Ports — Update these values if your environment uses non-default ports.
JSON 
{
  "$schema": "./zowe.schema.json",
  "profiles": {
    "BankOfZDemo": {
      "properties": {
        "host": "<your host>",
        "rejectUnauthorized": false
      },
      "secure": ["user", "password"],
      "profiles": {
        "rseapi": {
          "type": "rse",
          "properties": {
            "port": 8195,
            "basePath": "rseapi",
            "protocol": "https"
          }
        },
        "zosmf": {
          "type": "zosmf",
          "properties": {
            "port": 10443
          }
        },
        "ssh": {
          "type": "ssh",
          "properties": {
            "port": 22
          }
        },
        "tso": {
          "type": "tso",
          "properties": {
            "account": "<account>",
            "codePage": "1047",
            "logonProcedure": "<logon procedure>"
          }
        },
        "zOpenDebug": {
          "type": "zOpenDebug",
          "properties": {
            "dpsPort": 8192,
            "rdsPort": 8194,
            "dpsContextRoot": "api/v1",
            "dpsSecured": true,
            "authenticationType": "basic",
            "uuid": "4267a0f6-b756-4f3c-b900-0b959b4567c3"
          }
        }
      }
    }
  },
  "defaults": {
    "zosmf": "BankOfZDemo.zosmf",
    "tso": "BankOfZDemo.tso",
    "ssh": "BankOfZDemo.ssh",
    "rse": "BankOfZDemo.rseapi",
    "zOpenDebug": "BankOfZDemo.zOpenDebug"
  },
  "autoStore": true
}

4.2 Verifying Connectivity

To verify that your profile is correctly configured, connect to your z/OS system using the Zowe Explorer view in your IDE, or by using the Zowe CLI:

BASH 
zowe zosmf check status
zowe rse check status

If the connection fails, verify that the host, ports, and credentials are correct and that the corresponding services are running on z/OS.

5. Deployment Tooling

How your local changes reach z/OS depends on your chosen deployment workflow. There are three deployment workflows available:

Workflow Tooling Required Description
Zowe CLI Zowe CLI + IBM RSE API plug-in Deploys via the RSE API using Zowe CLI commands.
GRUB GRUB (Git Remote User Build) Syncs changed files directly to z/OS USS after each save, without requiring a Git commit.
Direct USS None Connect directly to z/OS USS via SSH and run setup scripts manually.

The sequence diagram below shows the overall local setup flow from start to finish:

sequenceDiagram participant Dev as Developer participant IDE as IDE participant Profile as Zowe Profile participant CLI as Zowe CLI participant GRUB as GRUB participant zOS as z/OS USS Dev->>IDE: Install extensions & verify Java 21 Dev->>Profile: Create ~/.zowe/zowe.config.json Profile-->>IDE: Credentials available to Zowe Explorer & Debugger Profile-->>CLI: Credentials available to Zowe CLI alt Zowe CLI Workflow Dev->>CLI: npm install -g @zowe/cli Dev->>CLI: zowe plugins install @ibm/rse-api-for-zowe-cli CLI->>zOS: zowe zosmf check status CLI->>zOS: zowe rse check status zOS-->>CLI: Connection confirmed CLI->>zOS: Deploy files via RSE API else GRUB Workflow Dev->>GRUB: Install GRUB Dev->>GRUB: Configure remote host, user, path & post-sync command GRUB->>zOS: Sync changed files via SSH zOS->>zOS: Run setup-remote.sh (post-sync hook) zOS-->>Dev: Setup complete else Direct USS Workflow Dev->>zOS: SSH directly to USS zOS-->>Dev: Run setup scripts manually end

5.1 Zowe CLI Setup

Zowe CLI is used by the Bank of Z deployment scripts to communicate with z/OS USS. It creates workspace directories, clones the repository on USS, and runs remote setup commands.

5.1.1 Prerequisites

  • Zowe profile configured. See Section 4 — Zowe Profile Setup.
  • Node.js >=22.22.1 <23. Verify the version:
BASH 
node -v
  • npm >=10.9.4 <10.10.0. Verify the version:
BASH 
npm -v

5.1.2 Installing Zowe CLI

BASH 
npm install -g @zowe/cli@zowe-v3-lts

Verify the installation:

BASH 
zowe --version

5.1.3 Installing the IBM RSE API Plug-in

The IBM RSE API plug-in is required for setup-local.sh to run USS commands and manage files on the target z/OS system.

BASH 
zowe plugins install @ibm/rse-api-for-zowe-cli

Verify that the plug-in is installed:

BASH 
zowe plugins list

5.1.4 Verifying the Zowe CLI Setup

Confirm that Zowe CLI can connect to your z/OS system using your configured profile:

BASH 
zowe zosmf check status
zowe rse check status

5.2 GRUB Setup

GRUB (Git Remote User Build) syncs local file changes directly to z/OS USS without requiring a Git commit, then runs a configured post-sync script on USS. Bank of Z uses this capability to run the setup and deployment scripts automatically after each sync.

5.2.1 Installing GRUB

Follow the GRUB installation instructions for your environment. GRUB is available from the IBM Z development tooling portfolio.

5.2.2 Configuring GRUB for Bank of Z

After installing GRUB, configure it with the following settings:

Setting Description Example
Remote host Host name or IP address of your z/OS USS system. myzos.example.com
Remote user Your USS user ID. IBMUSER
Remote path The path where the Bank of Z repository is synchronized. This should match sandbox.path in .setup/config/config.yaml with /Bank-of-Z appended. /usr/local/sandboxes/bank-of-z/Bank-of-Z
Post-sync command The command GRUB runs on z/OS USS after each synchronization. bash <remote-path>/.setup/setup-remote.sh

The post-sync command example:

BASH 
bash /usr/local/sandboxes/bank-of-z/Bank-of-Z/.setup/setup-remote.sh

5.2.3 How GRUB Works with Bank of Z

The diagram below illustrates the GRUB sync and deployment flow:

sequenceDiagram participant Dev as Developer participant GRUB as GRUB Client participant USS as z/OS USS Filesystem participant Script as setup-remote.sh Dev->>GRUB: Trigger sync (save / manual) GRUB->>GRUB: Compute patch of local changes\n(no Git commit required) GRUB->>USS: Transfer only changed files via SSH USS-->>GRUB: Files applied GRUB->>USS: Run post-sync hook USS->>Script: Execute setup-remote.sh Script->>Script: Detect Bank-of-Z repository context Script->>Script: Run Stage 1 — Environment setup Script->>Script: Run Stage 2 — Build Script->>Script: Run Stage 3 — Deploy Script-->>Dev: Setup & deployment complete

When you trigger a GRUB sync:

  1. GRUB computes a patch containing the local changes since the previous sync. No Git commit is required.
  2. The patch is applied to the Bank of Z directory on z/OS USS.
  3. The post-sync hook runs setup-remote.sh on z/OS USS.
  4. setup-remote.sh detects that it is running inside the Bank-of-Z repository and automatically runs all three setup stages.

After the initial deployment, subsequent syncs are typically fast because only changed files are transferred.

The table below summarises the complete local tools setup sequence:
